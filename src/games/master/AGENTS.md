## 实现

MasterGame.vue（Emoji 大师 / 羊了个羊闯关玩法：分层堆叠 + 遮挡判定、7 格收集槽三消、关卡难度曲线（组数 8→32（24→96 张，已是布局容量上限）、种类 **7→18**、层数 2→8，第 50 关到顶，之后关数无限；同一种可出多组，张数恒为 3 的倍数）、无计时器、无洗牌道具、顶部统计条底部有进度条（已消卡片/本关总卡片）、操作区左侧显示「层数 · 种类」、新游戏二次确认、开局/恢复时自下层向上逐张堆叠入场；游戏区本身是一张带底色的卡片（`--board-bg` + `--card-radius` + 8px 内边距，与连连看 / 消消乐同款——卡片坐标按 `layout` 的 `BOARD_PAD` 一起算，改内边距要同步改 `unit` 与 `--board-h`）；被压住的卡片**一律不透明**（depth-N 仅作样式钩子），只靠 `filter: brightness(0.5)` 变暗表示不可点；层数只影响视觉，能不能点仍由 `freeIds` 判定；连点时每张牌各播一条独立飞行动画（互不等待，flights 数组），落格用 settling 做重入保护、通关判定要等 flights 清空）+ board.js（纯逻辑：难度曲线 + 错位分层摆放（禁止两张卡片完全重叠、不让任何卡片被彻底遮住）+ buildTripleBag/dealAlongOrder 保证可解的发牌）+ i18n.js（route /master，key 前缀 __emoji_master__）

## 两种牌面模式（玩法完全一样）

`board.js` 里 `MODE_EMOJI` / `MODE_MAHJONG` 只影响**牌面池**与**难度曲线**，其余逻辑（分层堆叠、
遮挡判定、收集槽三消、可解发牌）一个字都没改：

| | emoji 模式 | 麻将模式 |
| --- | --- | --- |
| 牌面池 | `shared/emojis.js` 的 `EMOJIS` | `MAHJONG_KEYS`：m/s/p 各 1~9 + 字牌 1~7 = **34 种** |
| 种类曲线 | 顺着 50 关线性 7 → 18 | 跟着**组数**走：`kinds = round(triples × 0.8)`，夹在 10~26 |
| 牌面渲染 | 直接写字符（`{{ tile.emoji }}`） | `<MahjongTile>`，`emoji` 字段当 key（`'m5'` / `'z3'`）→ `faceOf()` 拆成 suit/value |

`emoji` 字段在两种模式下都只是**牌的标识字符串**（比对、分组、存档全用它），所以三消逻辑零改动。

**难度对照**（组数取自同一条曲线；「出现 6 张」= 一种牌分到 2 组）：

| 关卡 | 组数 | emoji：种类 / 出现 6 张 | 麻将：种类 / 出现 6 张 |
| --- | --- | --- | --- |
| 1 | 8 | 7 / 1 | **8 / 0** |
| 10 | 12 | 9 / 3 | 10 / 2 |
| 30 | 22 | 14 / 8 | **18 / 4** |
| 50 | 32 | 18 / 14 | **26 / 6** |

即：麻将模式**种类更多**（要同时记住的牌面更多）且**同一种出现 6 张的情况减半以上**。

### 麻将模式下「卡片本身就是一块麻将牌」

用户要求：**不是「正方形底 + 里面一张小牌」，而是卡片本身就长成麻将牌的形状**。
做法是把「格距」参数化 —— `board.js` 里 `pitchOf(mode)`：

| | 格距（单位） | 底层格点 | 卡片尺寸 |
| --- | --- | --- | --- |
| emoji | `{x: 2, y: 2}` | 7×7（与改动前**完全一致**） | 44×44 方牌 |
| 麻将 | `{x: 1.56, y: 2}`（1.56 = 2 × 131/168） | 8×7 | **34×44 竖牌** |

- 格距**就是牌面尺寸**，所以牌与牌正好挨着；遮挡判定改成按轴比较
  （`|Δx| < pitch.x && |Δy| < pitch.y`）—— 这与「矩形是否真的相交」等价，**emoji 模式下就是原来的 `< 2 && < 2`**。
- 四象限判定（`fullyCovered` / 摆放时的 `hiddenAt`）用**半个格距**当偏移（emoji 就是 ±1，不变）。
- 各层可放置区域改成用**单位**表示（`LAYER_EXTENTS = [14,12,12,10,8,6,4,4]`），列/行数按格距换算 ——
  于是麻将模式底层从 7 列变 8 列，容量反而更大（总格点 179 → 207），满级 96 张照样放得下。
- 牌面（`MahjongTile`）**填满卡片内框**：`faceVars(w, h)` 给的是 `w−2 / h−2`（减掉 1px 边框）。
- **托盘槽位也跟着变**：槽位盒子仍是方形格距，但底板形状用 `.slot::after` 画（宽 = 格距 × 131/168），
  托盘卡同样做成竖牌并在格距里居中 —— 否则又变成「方底 + 小牌」。
- **飞行的落点宽度**要按牌面形状算（`to.width × FACE_RATIO`），否则落到托盘时会横着跳一下。
- 实测（375）：emoji 44×44 / 麻将 34×44（比 0.77）、槽位底板 41.6 → 32.4、托盘卡 32×42 且牌面**正好填满**。
- **正确性验证**（关键）：逐张比较「逻辑判定的 covered」与「DOM 矩形是否真的被更高的牌压住」——
  第 1/12/25/38/50 关、两种模式各测一遍：牌数 24/39/60/78/96、层数 2/3/5/7/8 都与曲线一致，
  **漏判 0、误判 0**（既不会「看着被压住却可点」，也不会「没被压住却变暗」）。

## 立体卡片（3D）

盘面 / 托盘 / 飞行中的卡片都是**立体的**：正面 + 底部一条厚度 + 落地阴影，像从正面偏下方斜着看过去
（和麻将英雄的牌同一套做法）。三处共用 `<style>` 顶部的 `@mixin card-3d($lip)`，
`$lip` 传厚度的尺寸表达式 —— 牌 `var(--tile-lip)`（= 牌面宽 × 0.07，由 `layout` 写进变量）、
托盘卡 `var(--tray-lip)`、
飞行卡 `var(--lip, 3px)`（它是 Teleport 到 body 的，拿不到页面上的变量，所以 `flyStyleOf()` 按飞行尺寸
写进行内样式的 `--lip`）。侧面色用 `color-mix(in srgb, var(--card-bg-color) 74%, #000)` 得到：
本作的卡面跟主题走，浅色是白 → 灰、深色是深灰 → 更深。被压住的卡（`.covered`）**保留厚度**，
`filter: brightness(0.5)` 会把阴影一起压暗，这样叠起来仍然是一摞有厚度的牌（原来那行 `box-shadow: none`
已删）。

**厚度要留出空间，而且要在卡所在的那一层留**（这个坑麻将英雄分册里记过详细版，这里说本作的具体做法）：

- 盘面：底部内边距用 `--board-pad-b = --board-pad + --lip`；同时把 `unit` **反解小一点**，
  让「14 格 + 内边距 + 厚度」的总高与加立体之前**完全一致**（`u = (14u₀ + 2r) / (14 + 2r)`，r = 0.07），
  否则小屏本来就在滚动的高度会再多出 5px。实测 320×568 加立体前后都是 46px 溢出、360×640 都是 19px、
  390×844 都是 0（这页在小屏本来就滚，是历史情况，不是这次引入的），牌只小约 1%。
- 托盘：卡片 `top: 8px`、高 `--slot`，底部那 7% 厚度落在托盘 8px 的内边距里，**托盘高度公式不用改**。
- 最下一排（y = 12 半格）实测：牌面底距盘面底 21.7px、连厚度 19.7px、连阴影 16.4px，都在盘面内；
  托盘卡连厚度距托盘底 4.9px（同样是那 8px 内边距在兜）。

### 落格交接不能闪（飞行卡 → 托盘卡）

**现象**：卡片飞进下方暂存区、落格的那一刻会闪一下（卡片先消失、再从透明淡回来）。
逐帧采样（`requestAnimationFrame` 里查 DOM 里有没有卡覆盖槽位中心，注意
`elementFromPoint` 会跳过 `pointer-events: none` 的 `.fly-card`，必须直接查 DOM）：

```
改动前： S S … F F F F F F  T~0.00 T~0.00 T~0.07 T~0.22 … T~1.00 T T …
改动后： S S … F F F F F F  T T T T T T …
```

**两个原因**：① `fly()` 里先 `flights.value = filter(...)`（飞行卡立刻从 DOM 消失）**之后**才
`tray.value.splice(...)` 插托盘卡，中间至少有一帧「两张都不在」；② 托盘卡带
`animation: card-pop 0.2s backwards`，而 `card-pop` 是 `opacity: 0 → 1`，所以即便插进去了，
它也会从透明重新淡入 —— 这一下淡入就是肉眼看到的闪烁。

**改法**：先插托盘卡并 `await nextTick()` 等它渲染出来，**再**撤飞行卡；同时给刚落格的卡打
`fresh` 标记跳过 `card-pop`（`.tray-card.fresh { animation: none }`）。普通入场 / 恢复存档的卡
仍照常播 `card-pop`。另外飞行卡在动画末尾会被缩放到与托盘卡同尺寸，而两者的厚度与阴影都是
按各自尺寸算的，所以交接那一刻是像素级对齐的 —— 这也是飞行卡要带 `card-3d` 的原因
（原来飞行卡用的是 `--shadow-float`，与托盘卡的 `--card-shadow` 不一致，交接时阴影会跳一下）。

**通用教训**：一个「临时元素」把位置交接给一个「常驻元素」时，永远要**先让接收方出现、再撤走来源**，
并且**跳过接收方的入场动画**（它已经在屏幕上了，再播一次入场就是闪）。
