## 三种牌面模式（玩法完全一样）

`board.js` 里 `MODE_EMOJI` / `MODE_POKER` / `MODE_MAHJONG` 只影响**牌面池**、**格距**与**难度曲线**，
其余逻辑（分层堆叠、遮挡判定、收集槽三消、可解发牌）一个字都没改。切换顺序是 `MODE_ORDER`
（emoji → 扑克牌 → 麻将 → emoji，用户要求），`switchMode()` 按它取下一个。

| | emoji | 扑克牌 | 麻将 |
| --- | --- | --- | --- |
| 牌面池 | `shared/emojis.js` 的 `EMOJIS` | 组件里的 `POKER_FACES`：52 张（`'h7'`） | `shared/mahjongFaces.js` 的 `MAHJONG_FACES`：34 种 |
| 种类曲线 | 顺 50 关线性 7 → 18 | **同 emoji**（只补模式，没改难度） | 跟着**组数**走：`round(triples × 0.8)`，夹 10~26 |
| 牌面渲染 | 直接写字符（`{{ tile.emoji }}`） | `<CardItem mini>`：`pokerFaceOf()` 把 key 拆成 num/type | `<MahjongTile>`：`faceOf()` 拆成 suit/value |

`emoji` 字段在三种模式下都只是**牌的标识字符串**（比对、分组、存档全用它），所以三消逻辑零改动。

**难度对照**（组数取自同一条曲线；「出现 6 张」= 一种牌分到 2 组）：

| 关卡 | 组数 | emoji：种类 / 出现 6 张 | 麻将：种类 / 出现 6 张 |
| --- | --- | --- | --- |
| 1 | 8 | 7 / 1 | **8 / 0** |
| 10 | 12 | 9 / 3 | 10 / 2 |
| 30 | 22 | 14 / 8 | **18 / 4** |
| 50 | 32 | 18 / 14 | **26 / 6** |

即：麻将模式**种类更多**（要同时记住的牌面更多）且**同一种出现 6 张的情况减半以上**。

### 牌面模式下「卡片本身就是一张牌」

用户要求：**不是「正方形底 + 里面一张小牌」，而是卡片本身就长成麻将牌的形状**。
做法是把「格距」参数化 —— `board.js` 里 `pitchOf(mode)`：

| | 格距（单位） | 底层格点 | 卡片尺寸 |
| --- | --- | --- | --- |
| emoji | `{x: 2, y: 2}` | 7×7（与改动前**完全一致**） | 44×44 方牌 |
| 扑克牌 | `{x: 1.333, y: 2}`（2/3，扑克是 2:3 的竖牌） | 10×7 | **29×44 竖牌** |
| 麻将 | `{x: 1.56, y: 2}`（1.56 = 2 × 131/168） | 8×7 | **34×44 竖牌** |

实测（375，切一圈）：emoji 44×44 / 扑克 29×44 / 麻将 34×44，槽位底板 41.6 → 27.7 → 32.4，
三套存档 key 并存，切回 emoji 时盘面与之前**完全一致**（同指纹）。扑克模式下卡片盒透明、无阴影，
真正显示的是 `CardItem`：盘面 25×38（2:3）、托盘 24×37，飞行落格与托盘卡尺寸差 0。

- 格距**就是牌面尺寸**，所以牌与牌正好挨着；遮挡判定改成按轴比较
  （`|Δx| < pitch.x && |Δy| < pitch.y`）—— 这与「矩形是否真的相交」等价，**emoji 模式下就是原来的 `< 2 && < 2`**。
- 四象限判定（`fullyCovered` / 摆放时的 `hiddenAt`）用**半个格距**当偏移（emoji 就是 ±1，不变）。
- 各层可放置区域改成用**单位**表示（`LAYER_EXTENTS = [14,12,12,10,8,6,4,4]`），列/行数按格距换算 ——
  于是麻将模式底层从 7 列变 8 列，容量反而更大（总格点 179 → 207），满级 96 张照样放得下。
- 牌面尺寸：**麻将**靠 `cardFaceVars()` 挂在卡片盒上，**扑克**必须把 `pokerVars()` **内联在 `CardItem`
  自己身上**（⚠️ 见下面第一个坑）。两种竖牌的共同铁律：**高要由宽按真实比例反算，不能两边都减 2** ——
  麻将 `--mj-h = --mj-w × 168/131`、扑克 `--height = --width × 1.5`。两边都减 2 会把长宽比拉偏
  （麻将 0.7798 → 0.759），雪碧图/牌面被拉伸、`background-position` 取景跟着偏，现象就是
  **「牌没在正中间、右侧留白、左上角漏出隔壁那张牌」**（玩家报的正是这个）。扑克还比格子小一圈
  （用户要求「适当小一点」）：`POKER_INSET = 0.88`，在格子里居中。
- ⚠️ **坑一：`CardItem` 的 `.card` 是 `content-box` + 1px 描边**，比它的 `.card-wrapper` **大 2px**，
  而且绝对定位在 wrapper 的 `0,0` —— 于是可见的扑克牌会**往右下各偏 1px**（实测偏移 `[1, 0.99]`，
  看着就是「牌没居中」）。两处一起改才对：`pokerVars()` 传 `--width/--height = 目标 − 2`，
  样式里再用 `:deep(.card) { left: -1px; top: -1px }` 把它挪回同心（wrapper 自己由卡片盒 flex 居中）。
  改完实测可见牌居中偏移 `[0, -0.01]`。
- ⚠️ **坑二：`CardItem` 的 `.card-wrapper` 自己声明了 `--width: 60px; --height: 90px`**，把变量挂在
  父元素上会被本地声明压掉，牌会渲染成 60×90 撑破 29×44 的格子（现象是「背景不按扑克牌宽高比渲染」）；
  麻将能靠继承是因为 `MahjongTile` 用的是 `var(--mj-w, 44px)` 这种**回退值**、不是声明。
- ⚠️ **坑三：卡片盒的圆角要跟牌面一致**，否则盒子的白角会从牌面四角漏出来（看着也像「没居中」）：
  麻将模式给卡片盒 `border-radius: calc(var(--mj-w) × 0.09 + 1px)`（+1 是盒子自己的 1px 描边），
  emoji 保持全局 `--radius-tile`。
- **扑克模式下卡片盒要「让开」**：`.tile.poker` / `.tray-card.poker:not(.clearing)` / `.fly-card.poker`
  把底色、描边、阴影全部取消，整张牌交给 `CardItem` 自己画（和 猎手 / 对对碰 / 侦探的
  `.poker .face` 同一做法）。⚠️ **这个块必须放在 `<style>` 的最末尾**：`.tile` 的底色是嵌在
  `.wrapper { .tile { … } }` 里编译出来的 `.wrapper .tile[data-v]`，与 `.tile.poker[data-v]` **同优先级**，
  靠「谁在后面谁赢」—— 放在中间会被它盖掉（实测底色仍是白的）。托盘卡用 `:not(.clearing)` 避开，
  免得把三消清除时的高亮也抹了。
- **托盘槽位也跟着变**：槽位盒子仍是方形格距，但底板形状用 `.slot::after` 画，托盘卡同样做成竖牌并在
  格距里居中 —— 否则又变成「方底 + 小牌」。⚠️ **底板的尺寸必须等于「真正显示出来的那张牌」**，
  三种模式各不相同：emoji = 卡片盒本身（字符填满）、麻将 = 盒 − 2（牌面就是盒内框）、
  扑克 = `pokerSize()` 的结果（CardItem 那张牌比盒再内缩 12%）。只按「盒 × 宽高比」画的话，
  扑克模式会出现「框比牌大一圈、边界有落差」（玩家报的就是这个）——
  实现上就是 `layout` 里的 `slotShape` 按模式取，别再用 `slotW`/`slot` 直接当底板尺寸。
  实测（375）：emoji 底板 42×42 = 牌 42×42、麻将 30×40 = 30×40、扑克 24×37 = 24×37，**差值全 0**（同心同尺寸）。
- **飞行的落点宽度**要按牌面形状算：比例取「托盘卡宽 / 槽位宽」（`layout.slotW / layout.slot`，三种模式通用：emoji 是 1、扑克 2/3、麻将 131/168），否则落到托盘时会横着跳一下。实测扑克模式落格那一刻飞行卡的牌面 24×37、托盘卡 24×37，**差 0**（像素级对齐）。
- 实测（375）：emoji 44×44 / 麻将 34×44（比 0.77）、槽位底板 41.6 → 32.4、托盘卡 32×42 且牌面**正好填满**。
- **正确性验证**（关键）：逐张比较「逻辑判定的 covered」与「DOM 矩形是否真的被更高的牌压住」——
  第 1/12/25/38/50 关、**三种模式**各测一遍：牌数 24/39/60/78/96、层数 2/3/5/7/8 都与曲线一致，
  **漏判 0、误判 0**（既不会「看着被压住却可点」，也不会「没被压住却变暗」）。

## 卡片样式（**扁平的**）

**没有立体感**（玩家明确要求去掉）：盘面牌 / 托盘卡 / 飞行卡都是普通扁平卡片 ——
底色 + 1px 描边 + `box-shadow: var(--card-shadow)`，没有底部那条厚度、也没有落地投影。
三种牌面模式（emoji / 扑克 / 麻将）一致。

历史：这里原来有一套 `@mixin card-3d($lip)`（正面 + 底部实心厚度 + 落地阴影，和麻将英雄同款），
`LIP_RATIO = 0.07` 的厚度画在元素外面，所以盘面底部内边距要加上它、`unit` 还要反解小约 1% 把厚度
补回来（`u = (14u₀ + 2r) / (14 + 2r)`）。**去掉立体感后这些补偿全部删掉**：`unit` 直接用
`(avail − 2 × BOARD_PAD) / 14`，`--board-h = 14u + 2 × BOARD_PAD`，`--board-pad-b = BOARD_PAD`。
实测页面总高与改之前一致（375×667 下仍是 10px 溢出，是历史情况），但卡片大了约 1%。


### 落格交接不能闪（飞行卡 → 托盘卡）

**现象**：卡片飞进下方暂存区、落格的那一刻会闪一下（卡片先消失、再从透明淡回来）。
逐帧采样（`requestAnimationFrame` 里查 DOM 里有没有卡覆盖槽位中心，注意
`elementFromPoint` 会跳过 `pointer-events: none` 的 `.fly-card`，必须直接查 DOM）：

```
改动前： S S … F F F F F F  T~0.00 T~0.00 T~0.07 T~0.22 … T~1.00 T T …
改动后： S S … F F F F F F  T T T T T T …
```

**两个原因**：① `fly()` 里先 `flights.value = filter(...)`（飞行卡立刻从 DOM 消失）**之后**才
`tray.value.splice(...)` 插托盘卡，中间至少有一帧「两张都不在」；② 托盘卡带
`animation: card-pop 0.2s backwards`，而 `card-pop` 是 `opacity: 0 → 1`，所以即便插进去了，
它也会从透明重新淡入 —— 这一下淡入就是肉眼看到的闪烁。

**改法**：先插托盘卡并 `await nextTick()` 等它渲染出来，**再**撤飞行卡；同时给刚落格的卡打
`fresh` 标记跳过 `card-pop`（`.tray-card.fresh { animation: none }`）。普通入场 / 恢复存档的卡
仍照常播 `card-pop`。另外飞行卡在动画末尾会被缩放到与托盘卡同尺寸，两者现在用**同一条**
`box-shadow: var(--card-shadow)`，所以交接那一刻是像素级对齐的
（原来飞行卡用 `--shadow-float`、托盘卡用 `--card-shadow`，阴影不一致会跳一下；
更早还各有按尺寸算的立体厚度）。

**通用教训**：一个「临时元素」把位置交接给一个「常驻元素」时，永远要**先让接收方出现、再撤走来源**，
并且**跳过接收方的入场动画**（它已经在屏幕上了，再播一次入场就是闪）。
