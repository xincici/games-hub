# 麻将传奇（`src/games/legend/`）

> 这是根目录 [`AGENTS.md`](../../../AGENTS.md) 的**游戏分册**：只讲这个游戏自己的实现、存档 key
> 和踩过的坑。**改这个游戏前先读这里**；跨游戏共用的约定（视觉语言、共享组件、新增游戏流程）看根目录。
>
> - 路由：`/#/legend`
> - i18n key 前缀：`__mahjong_legend__`
> - 共享组件：`src/shared/`；牌面复用麻将英雄 / 雀圣那张雪碧图的**条牌**
>   （`MahjongTile` 加了 `suit` 属性，本作传 `suit="s"`，默认值仍是 `'p'`，麻将英雄不受影响）

## 玩法

**8 行 × 7 列**的游戏区（`ROWS × COLS`）。**开局底部先摆两行**（共 14 张），而且 `initialGrid()`
会**重发到这两行没有任何可消的组**为止（见下）；这两行（以及恢复记录时的整盘）按「左上 → 右下」的
波浪逐张出现，之后随机的一行条牌从底部**升起**：

- 点**空格**＝把手上的牌落到那一列（它会顺着这一列往下掉、落在已有牌上面；点哪一行不重要）；
- 点**已有牌**＝用手上这张把它替换掉（被换掉的那张直接弃掉）。

候选区显示当前要出的牌与后面两张。玩家操作之后检测**相邻**的牌（同一行/列里紧挨着的算一段）：

| 牌组 | 分数 | 说明 |
| --- | --- | --- |
| 顺子 | 100 | 三张点数连续（**与顺序无关**：3,2,1 也是顺子）|
| 刻子 | 200 | 三张相同 |
| 杠 | 300 | 四张相同 |

牌面**不只是条牌**：以 `HONOR_RATE = 0.12` 的概率出**字牌**（東南西北中發白，取值 10~16，
雪碧图里的 `z1`~`z7`）。字牌**只能靠刻子 / 杠消除**（点数不连续，凑不出顺子），
这是加难度的主要来源；出现频率按用户要求压得不高（实测占全部牌的 12~13%）。

一次消除超过一组时，从第二组起每组再加 100（`multiBonus`）。

**核心节奏**：这次操作**消掉了牌** → 底部不升新行；**没消掉** → 底部升一行随机新牌，
并把整盘往上顶一格（这一行新牌自己也可能直接消除计分）。牌永远不会悬空：消除之后悬着的牌
自动下落，下落又消除就是**连击**，从第二连起每连额外加 100（`chainBonus`）。

**失败**：有牌到达最顶行（第 0 行）后，再有一次「没消除」的操作要升行时，它会被挤出棋盘 → 游戏结束。
也就是最顶行是最后机会：要么消掉它，要么就会被顶出去。**没有过关概念**（单局制、只记最高分）。

## 实现要点

- **开局盘面 `initialGrid(rand)`**：底部两行随机铺满，然后 `findGroups` 检查 —— 有组就整盘重发
  （最多 200 次兜底）。这两行只有 2 张高，纵向凑不出组（组至少 3 张），所以只需横向三个窗口干净；
  实测随机一行「干净」约 7 成，**重发次数 p50 = 1、p90 = 4、max = 13**；5000 次开局里
  **有可消组的 0 次**、牌数恒为 14、占用的行恒为第 6/7 行。开局这两行按「左上 → 右下」的波浪铺开（见下面「动画」一节），
  不再是「从棋盘下方升起」——用户明确要求波浪式渲染。
- **牌值域 1~16**：1~9 = 条（点数就是点数），10~16 = 東南西北中發白。`suitOf(v)` / `faceOf(v)`
  把值映射成雪碧图的 `s1..s9` 与 `z1..z7`（`MahjongTile` 的 `suit` 属性就是干这个的），
  `MAX_VALUE = 16` 用于存档校验。**判顺子时必须先卡「三张都是条牌」**（`<= HONOR_BASE`）——
  否则「9条 + 東 + 南」排序后是 9,10,11 会被算成连续三张（这是加字牌时最容易漏的一处）。
- 纯逻辑在 `board.js`：`emptyGrid` / `dropRow` / `settle`（重力）、`placeTile` / `replaceTile`
  （参数是**点数**，内部统一 `makeTile`）、`findGroups` / `clearGroups`、`spawnRow`（升行 + 溢出判定）、
  `multiBonus` / `chainBonus`。
- **判组用「每段一个 DP」而不是贪心**：同一行/列里被空格分开的算两段，每段求「分数最高的拆法」。
  贪心会漏：`1,2,3,3,3` 先拿顺子只剩 100，先拿刻子能拿 200（实测 DP 选刻子）。
  顺子**与顺序无关**（排好序再判连续），因为玩家从下往上码成 1,2,3，自上而下扫就是 `[3,2,1]`。
- **动画**：牌的 `top` 走 `transition: top var(--move-ms)`，`--move-ms` 平时 200ms、升行时 240ms；
  升行上顶与消除后下落都靠它。新一行升起是把 7 张牌的 `fromRow` 先设成 `ROWS`（棋盘下方）、
  下一帧清掉 —— 配合棋盘的 `overflow: hidden` 就有「从底部升上来」的效果。
- **开局与恢复记录都是「左上 → 右下」的波浪铺开**（用户要求，照麻将英雄 / 雀圣那套）：
  `startDeal()` 置 `dealing = true` + `dealSeq += 1`，每张牌的 `animation-delay = (行 + 列) × 60ms`、
  动画是 `tile-wave 0.34s`（从左上方 `translate(-18px,-18px) scale(0.45)` 滑入到原位），
  `(ROWS-1 + COLS-1) × 60 + DEAL_MS` 之后收尾。
  **`dealSeq` 必须拼进 `:key`**（`:key="`${dealSeq}-${t.id}`"`）—— 不拼的话 `newRun()` / `restore()`
  里 uid 从 1 重来、key 撞上，Vue 会复用元素、**入场动画根本不重播**（雀圣分册里记过同一个坑）。
  实测：初始化 14 张的延迟 0.36 → 0.78s（= (6+列)×60 与 (7+列)×60）、恢复 16 张的延迟 0.24 → 0.78s，
  都严格是 (行+列)×60；中途截图能看到左下已滑入、最右一列还没出现。
- **落子 / 替换是「浮牌从候选区飞过去」**（照麻将英雄的 `flyTo`，用户指定）：
  `commitPlacement` 式地**先把数据落位**，但落点那张牌先隐身（`incomingId` → `.tile-slot.incoming
  { opacity: 0 }`），同时把一张 `.fly-tile`（`position: fixed; z-index: 60`，内含手牌尺寸的牌）
  放在候选牌中心，`nextTick + rAF` 后改成 `translate(dx, dy) scale(格宽/手牌宽)`，
  由 `transition: transform 0.2s ease-out` 播过去；`FLY_MS = 210` 后清掉浮牌、落点显形。
  **浮牌必须挂在 `.wrapper` 层（fixed）**，否则会被棋盘的 `overflow: hidden` 裁掉。
  第一版是「先渲染在点击的那一行、下一帧再落下」，替换更是只有一个小弹出，都不对。
- **浮字与特效必须和闪烁同一帧触发**（用户报过「提示比动画早一步」）：顺序是
  **先落位 / 把牌从盘面拿掉 → 设 `clearing` → 再 `showFloat` + 震动 + 外圈闪光 + 撒花**
  （麻将英雄的 `settle()` 就是这个顺序：先改盘面、`clearing.value = gone`、最后 `announceCelebration`）。
  三个配套细节，缺一个就会出现「不同步」的观感：
  ① 浮字元素要**带 `:key="float.id"`**（`floatId` 自增），否则连击时 Vue 复用同一个元素、
     `celebrate-pop` 不会重播，新提示就像「悄悄换了行字」；
  ② 震动 / 闪光要先 `false` → **强制重排**（`void board.offsetWidth`）→ 再 `true`，
     否则连着第二次触发时类名没变化、动画不重播（麻将英雄的 `shakeBoard()` 就是这么写的）；
  ③ 震动动画 0.34s、外圈闪光 `board-celebrate` 0.9s（都用 `--celebrate-glow`，`App.vue` 里的全局变量）。
  实测时间线（60ms 轮询，构造一局必然连击的盘面）：+300ms 浮字「刻子 +200」与闪烁浮影同现；
  **+1020ms 一帧里同时出现**「刻子 +300 🔥 连击 ×2」+ 闪烁 3 张 + 震动 + 闪光 ✓；震动 340ms、闪光 900ms 后各自消失。
- **消除用单独的浮影层，而且必须先删后闪**（用户指出闪烁不对）：`clearing` 这个 Map 存
  `{id, v, row, col}`，**先把牌从 `grid` 里拿掉、再让浮影层播 `blink-clear`**，闪烁结束才 `settle`
  下落。第一版写成了「先闪、闪完再删」—— 那 0.12 透明度的几帧会被底下那张实牌透出来，
  看着完全不像闪烁（麻将英雄就是先删后闪）。实测闪烁期间盘面只剩没被消的牌、浮影层 3 张。
- 多消 / 连击：`burstConfetti` + 棋盘 `board-shake`，得分浮字显示「牌组名 / 连消 n 组」+「🔥 连击 ×n」
  （参考麻将英雄那套 `.celebrate`）。
- 尺寸：7 列受宽度约束，8 行受高度约束，取小（`min(24, …, 92)`）。高度预算扣掉顶栏/统计卡 262
  与下方候选区那一行 96。实测：390×844 → 棋盘 **341×486**、320×568 → **194×278**，
  两档文档高都等于视口高（**不出滚动条**）。

## 界面

- 统计条三格「**🏆 最高分 / ✨ 得分 / 🀄 消除**」（前两格按用户要求换过位置：最高分在前）。
- **「新游戏」没有二次确认**（用户要求）：两个入口（操作区那颗、结算浮层那颗）都直接调 `newRun()`，
  只清当前得分与盘面、**保留最高分**；本作是单局制，不在根目录「闯关游戏统一约定」的适用范围里，
  所以不挂 `ConfirmDialog`（那个约定是给有闯关进度的游戏用的）。
- **候选区与「新游戏」那一行照麻将英雄的实现**（用户指定，改过三轮才对上）：
  - **位置在游戏区上方**：顺序是「统计卡 → `.card.opt-area` → `.game-area` → 结算浮层」（第一版放在棋盘
    下面了，用户指出要参考麻将英雄 —— 那边就是操作区在上）；
  - **结构**：`.card.opt-area` > `.opt-half.hand`（当前牌 `.tile-slot.current` + `.preview` 里两张
    `.tile-slot.next`，**不画外部容器**）+ 右半只放「🎮 新游戏」按钮；
    **后两张的缩放按 `PREVIEW_SCALES = [0.8, 0.6]` 递减**（用户指定：第二张 0.8、第三张 0.6，
    实测渲染 35×45 与 26×34；槽位本身仍是 44 宽的布局盒，只缩视觉 —— 与麻将英雄缩预览的做法一致）；
    **没有分隔线、没有文字标签**（第一版自己加了 `当前 / 下一张` 标签和一条 `.divider`，已去掉）；
  - **槽位尺寸与牌面变量要分开**（照麻将英雄）：`slotVars = { width: 44px, height: 56px }` 给槽位，
    `handTileVars = { --mj-w: 44px, --mj-h: 56px }` 给牌。**第一版给候选牌传的是棋盘格子尺寸**
    （`tileVars` ≈ 46×59），看起来「差不多」其实不对，用户一眼就看出来了；
  - **主次**：`.hand .tile-slot.current .mj` 套 `outline: 2px solid var(--primary-bg)` + `outline-offset: 1px`，
    `.hand .preview` 压到 `opacity: 0.55`（这两条第一版改样式时漏了）；
  - **`.game-icon` 按钮样式必须自己写**（第一版压根没定义，按钮是浏览器默认样式）：`cursor: pointer;
    padding: 8px 16px; border: 0; border-radius: var(--radius-tile); background: var(--primary-bg);
    color: #fff; font-size: 14px; font-weight: bold`。
  - 实测（把两个游戏放一起比）：当前牌都是 **44×56**、预览牌 **35×45**、预览透明度 **0.55**、
    描边 **2px solid rgb(35,128,78)** + offset 1px、按钮 **96×39**（主色底 / 白字 / 14px / 700 / 圆角 8px /
    内边距 8px 16px）—— 逐项一致，传奇只是预览多一张（规则要求显示后两张）。
- 结算浮层在棋盘内（`inset: 0` + `box-sizing: border-box`），文案只有「顶出去了 / 本局得分 N」
  （原来还有一句「有牌升到顶格后被挤出了棋盘」，用户要求去掉），刷新最高分时多一行「新纪录诞生」。

## 坑

1. **`same(k)` 必须逐张比对**：第一版写成 `values[i + k] === values[i]`（只比首尾），于是 `[5,7,5]`
   被判成刻子、`[5,1,5]` 也是 —— 症状是「凭空多出 200/500 分」，离线跑一遍 `findGroups` 才抓到。
2. **`placeTile` / `replaceTile` 内部一定要 `makeTile`**：第一版直接把传进来的数字存进格子，
   于是刚落下的牌没有 `id`/`v`，`findGroups` 读到的全是 `undefined`、**刚落下的牌永远不参与判组**
   （页面表现是「落子后什么都不会发生」，但构建、控制台都没报错）。是给牌加了 `data-v` 断言才定位到的。
3. **判组与顺序无关**（见上）。
4. **模板里用了没定义的变量，Vue 不报错、只静默变 `undefined`**：第一版模板里写了 `handVars` /
   `previewVars` 而脚本里没定义 —— 和麻将英雄分册里记的是同一个坑，改完记得量一次候选牌尺寸。
5. **i18n 字典忘了注册**：注册表 `games.js` 里加了 `import` 与条目，但漏了文件末尾的
   `['legend', legendDict]` 注册表 —— 症状是**所有文案都是空字符串**（结算浮层只剩 emoji 和数字）。
6. **帮助文案是纯文本**：`help1..help5` 里写 Markdown 的 `**加粗**` 会原样显示出来（踩过，已去掉）。

## 存档（localStorage）

- `__mahjong_legend__state`：`{ phase, score, cleared, queue, grid }`（grid 只存点数，恢复时重新分配 id）
- `__mahjong_legend__best_1`：最高分（注册表 `recordsPrefix: '__mahjong_legend__best_'` + 1..1，
  正好被标题连点 5 次的清记录彩蛋命中）。**当前得分一超过最高分就立刻同步**（用户要求，`watch(score)`
  里更新并落盘），不再是等到这局结束才更新 —— 所以「最高分」是实时涨的。
  配套的 `beatBest` 单独记「这一局有没有刷新过纪录」，供结算浮层的「新纪录诞生」用：
  **不能再用 `score > best` 判断**，那时 best 已经被同步成 score 了（否则那行字永远不会出现）。
- `__mahjong_legend__help_showed`：帮助弹窗是否已弹过

失败结算也会存档：退出重进还是那个失败浮层（`phase: 'over'`），由玩家自己决定要不要开新局。

## 难度标定（离线，1 层贪心玩家，300 局/档，900 回合封顶）

| 字牌频率 | 实际字牌占比 | 900 回合内结束 | 存活 p50 / p90 / max | 分数 p50 / p90 |
| --- | --- | --- | --- | --- |
| 0（没有字牌）| 0% | 300/300 | 25 / 79 / 280 | 3100 / 10700 |
| 0.08 | 8.4% | 300/300 | 16 / 35 / 76 | 1900 / 4200 |
| **0.12（当前）** | **12.2%** | 300/300 | **12 / 26 / 77** | **1300 / 3200** |
| 0.18 | 18.4% | 300/300 | 10 / 21 / 45 | 1000 / 2200 |

**结论**：每格 12% 的字牌把贪心的存活中位从 25 回合压到 **12 回合**（约翻倍难度）、分数中位
3100 → 1300，同时字牌只占全部牌的 12% —— 既满足「加一点难度」也满足「频率不要太高」。
再往上调（0.18）收益递减且容易堵死盘面，所以定在 0.12。

**一个口径上的坑**：早期那版标定表写「存活 p50 = 366」，那是在**已经结束的那批局**里算的
（211/300 根本没在 800 回合内结束），不是整体分位数 —— 换字牌时统一了口径，才看出真实难度。
