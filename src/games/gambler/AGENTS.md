# 赌神（`src/games/gambler/`）

> 这是根目录 [`AGENTS.md`](../../../AGENTS.md) 的**游戏分册**：只讲这个游戏自己的实现、
> 存档 key 和踩过的坑。**改这个游戏前先读这里**；跨游戏共用的约定看根目录。
>
> - 路由：`/#/gambler`
> - i18n key 前缀：`__gambler__`
> - 共享组件：`src/shared/`（`i18n.js` / `Hearts.vue` / `ConfirmDialog.vue` / `resultDelay.js`）
>   与 `src/shared/mahjongTiles.js`（麻将雪碧图 + 花牌）

## 玩法一句话

展示区给一副 13 张**已听牌**的手牌（无字牌、可含花牌＝万能牌），玩家从下方 **27 张**牌面（万/条/筒）
**把能胡的牌全部选出来**（少一张都不算过），选错扣心、每关 2 颗；也可以直接「查看答案」，代价是本局失败。

## 实现

`GamblerGame.vue`（交互层）+ `board.js`（纯逻辑，**不 import 任何东西**，`scripts/check-gambler.mjs` 直接跑它）。

- **牌面**：三门 `m/s/p` 各 1~9 共 27 种 + 字牌 `z1~z7`（只在选择区当干扰项）+ 花牌 `f1~f8`。
  渲染一律用 `games/mahjong/MahjongTile.vue`，花牌就是 `suit === 'f'`（雪碧图第 6~7 行）。
- **听牌生成**（`newRound(level, rand)`）：先随机攒一副「4 组面子 + 1 对将」的 14 张 →
  把其中若干张换成花牌 → 去掉一张 → 13 张**必然听牌**。生成 40 个候选，按
  「答案个数 × 2 + 拆法数量 + 花牌 × 1.5」打分挑最复杂的那个。
- **胡牌判定**（`canWin` / `countWins`）：统一用**数拆法** —— 4 组面子 + 1 对将，
  花牌当万能牌补进刻子 / 顺子 / 将；⚠️ **补进去的花牌要计入该种牌的总数**（`subs` 记录），
  所以「手里 4 张 + 花牌再顶一张」判不和，严格守住单种 4 张。输入里只要有一种超过 4 张直接判不和。
- **答案集**（`winningPicks`）：对 27 种逐一试「加这一张能不能和」；`blocked`（手里已满 4 张）直接跳过。
  ⚠️ **答案不写进存档**，恢复时按手牌重算（`winningPicks` / `isBlocked`），免得手改存档就能看答案。
- **关卡曲线**（`levelConfig`）：花牌上限 0 → 1（第 5 关起）→ 2（第 12 关起）；
  答案个数 1~2 → 6~7（`RAMP`）；`maxPicks` 留 +1 的弹性，免得同一关永远是同一个答案数。
  **界面绝不显示答案个数**（用户明确要求）。
- **布局**（玩家要求）：分数区四格顺序是**最高关卡 / 关卡 / 连胜 / 生命**（「最高关卡」在「关卡」左边，
  生命在最右，里面放 `shared/Hearts.vue`）；
  操作区左边是「新游戏」、右边是「查看答案」（描边次要按钮，`.game-icon.ghost`）。
- **选择区**：`groups` 只有万/条/筒三行、**没有行首文字**（原先的 `.row-label` 已删），
  `board.js` 的 `SELECT_KEYS` 也收敛成三门 27 张（字牌既不进手牌也不进选择区）。
- **答案区**（`.answer-card`，夹在手牌与选择区之间）：玩家选中的牌会**从选择区飞进来**。
  飞行用**克隆**：`fromEl.cloneNode(true)` 贴到 `document.body`（fixed 定位到原位、`zIndex: 60`、
  自带 `filter: none` 抵消原位的置灰），量出来源与目标槽位的 rect 后用 `element.animate`
  把它 `translate + scale` 到目标（420ms，不 fill），落地后 `ghost.remove()`。
  ⚠️ **不要让来源元素自己飞**：那样原位在飞行期间会空出来（玩家反馈「所在位置不要空白」）——
  原位那张要立刻变 `.used` 留在原地，只有克隆在飞。
  目标槽位在飞行期间挂 `.landing { visibility: hidden }`，落地那一刻才现身
  （visibility 不影响布局，量位置照样准），所以也不会出现「两张同时在场」的闪。
  ⚠️ 恢复存档时，已选的是**答案**（手牌之外的牌），所以只能按 `KIND_KEYS` 校验 + 去重，
  早先写成 `filter(k => st.hand.includes(k))` → 刷新后答案区会被清掉大半。
- **已选走的不可再选**：选择区那张会挂 `.used`（`pointer-events: none` + 变淡），`pick()` 里也先挡一道。
- **失败统一走 `finishRound(kind)`**（异步，`kind = 'wrong' | 'reveal'`）：把玩家还没选出来的答案
  **一张一张 `await flyToAnswer()`**（每张之间 120ms，看得清）→ 全部落地后才
  `pickFailed = true`、`phase = 'lost'`、`streak = 0` 再 `save()`。
  扣完心是 `later(() => finishRound('wrong'))`（先让抖动播完），查看答案则是 `hearts = 0` +
  **立刻 `save()`** + `finishRound('reveal')`。
  失败**只有**选择区的 `.pick-mask` 这一种呈现（**只在 `.pick-card` 内**，所以答案区仍然看得见、方便复盘）——
  居中那个 `.result lose` 浮层已删除，现在 `.result` 只用于获胜；别再加回来，否则两种呈现会同时出现。
  ⚠️ 飞行期间（1~3s）`phase` 还是 `play` 而心里已是 0：`restore()` 对此直接按失败处理。
- **点错标红不可再选**：`missedKeys`（存档里是 `missed`，刷新后仍标红），模板里是 `missed: missedSet.has(key)`，
  样式 `.pick-tile.missed`（红线 + 变灰 + `pointer-events: none`），`pick()` 里也先挡一道。
- **遮罩按钮**：左边「重玩本关」、右边「新游戏」，**两颗都是主色绿**（`.game-icon`；
  曾经给「新游戏」用过白底描边的 `.ghost`，玩家要求统一成绿色，那条样式已删）；
  `.result-actions` 已经
  **提到 `.wrapper` 顶层**（原先嵌在 `.result` 里 → 遮罩里的那颗没有 `gap`，两颗挤在一起），
  现在浮层与遮罩共用同一套 `gap: 12px`。
  ⚠️ 查看答案用的橙色照抄 24 点的 `.answer-btn:not(:disabled) { background-color: var(--god-bg) }`
  （全局 `--god-bg = #c2410c`，白字 5.18:1）；禁用时仍是灰的。
- **交互**：点中答案 → 只亮一圈绿环（`.picked` 的 outline）；**不要**再加放大/闪烁
  （曾经有 `.popping` + `tile-pop` 关键帧，玩家要求去掉：牌已经飞进答案区，原位再弹一下很吵）；
  点错 → 抖一下 + 扣心（扣完 `later(lose)`）；
  选满 `picks` 自动判胜（没有确认按钮）。结算前用 `shared/resultDelay.js` 停 0.5s 让玩家看清结果。
- **动画**：展示区 13 张与选择区 34 张都用 `--i` 做错峰入场（`tile-in` 关键帧）；
  `roundId` 进 `:key`，所以**每换一关动画重播**。
- **选择区居中**：`groups` 三行各 9 张，内容宽 321px、卡片内宽 327px —— `.pick-row` 必须
  `justify-content: center`，否则那 6px 全落在右边（玩家反馈「没居中对齐」）。
- **尺寸**：手牌 13 张排一行、选择区每行 9 张，牌面尺寸按可用宽度算，
  ⚠️ **高必须由宽按 168/131 反算**（两边都减 2 会把长宽比拉偏，雪碧图被拉伸、取景偏 —— 麻将家族的老坑）。

## 存档（localStorage）

  - 赌神：`__gambler__*`
    - `__gambler__help_showed`（帮助弹窗是否弹过，注册表 `helpKey`）
    - `__gambler__level`（当前关卡）
    - `__gambler__best`（最高关卡；0 = 还没记录）
    - `__gambler__streak`（当前连胜；失败归零）
    - `__gambler__state`（局面：关卡、13 张手牌、已选中的 key、剩余 ❤️、阶段 play/won/lost）——
      **不含答案**，恢复时重算；胜利 / 失败都会停在结算层，由玩家自己点「下一关 / 重玩本关」。
    - 连点标题 5 次（`onScoreReset`）清掉以上全部并回到第 1 关。

## 坑

- **雪碧图 `ZOOM` 必须 ≥ 1.05，别改成 1**：共享的 `shared/mahjongTiles.js` 里 `ZOOM = 1.05` 是
  **必需的** —— 雪碧图每格四周都带了 1px 原图相邻行列的像素，放大 5% 正好把那圈邻居边缘推到
  元素之外。改成 1 之后牌贴着的那条边会露出**一条毛边/白线**（玩家反馈「新版本的麻将牌似乎有
  边框毛边，回退之后视觉就对了」）。代价是每边裁掉约 2.4%（≈3px 原图边缘），这是既定的取舍。
  （我曾据「格边像素是暗的」误判成那是牌自己的暗边而改成 1 —— 那个测量只看了一格中部，
  没看到边缘那圈邻居像素，结论是错的。）
  可见区间 = `[r + 0.5 − 0.5/k, r + 0.5 + 0.5/k]`，**只跟 k 有关、跟行数 n 无关** ——
  所以雪碧图从 5 行扩到 7 行（`ROWS` 5→7、`background-size` 735%×735%）时，
  只要 k 保持 1.05，原有 34 张牌面的渲染就与原版逐像素等价（用固定 `Math.random` 种子做整屏
  A/B 实测：差异 0.03%~0.08% 像素，全是 WebP 重编码噪声）。

- **答案不进存档**：存档里只存手牌，答案与置灰表都在恢复时重算。想改难度就改 `levelConfig`。
- **花牌顶替要计入总数**：`countMelds` 里的 `subs` 不能省，否则「同种 5 张也算和」。
- **`newRound` 别放 computed**：一次十几毫秒，开局 / 换关时调一次存进 ref。
- **牌面比例**：见上，「宽定高」是这个仓库的硬约定。
- **花牌雪碧图**：8 张花牌是从玩家给的素材裁出来贴进 `mahjong-tiles.webp` 的，位置在索引 **34~41**
  （⚠️ 不是 35~42：`SLOT_ORDER` 里 34 张牌面占 0~33，所以 `f1` 就是 34 —— 原来那格空白）。
  放进别的索引会整体错位一格，现象是「花牌显示成白板或隔壁那张」。
  素材里 8 张牌**不是等距**的（实测竖边 135/257/378/499/619/739/859，宽度 117~123），
  用 125 等分去裁会切进牌里；正确做法是取「每 125px 邻域内暗柱的最大值」当缝线，
  再按缝线中缝切出 8 张。
  ⚠️ **横竖两个方向都要按牌卡边线裁**：只按竖线裁、纵向取整张高度 0~185 的话，会把牌上下方的
  背景也带进来，卡面在格子里只占 ~85% 高度，看起来**又矮又胖**（玩家反馈「宽高比不同，很矮」）。
  横向边线用「每行暗像素数」找（实测上沿 y≈13、下沿 y≈175），裁 `[x0..x1] × [15..173]`
  再**等比**缩放到填满格高（122×159 → 129×168），卡面就和其他牌面一样满格（168/168）。
  改雪碧图要同步 `mahjongTiles.js` 的 `ROWS` / `SLOT_ORDER`。
