## 玩法

3×3 棋盘上的麻将消除：牌只有**一筒 ~ 九筒**这九种（点数 1~9），每种 4 张、共 36 张的牌墙 ——
和真麻将的筒子一样，所以这里**允许重复**（刻子本来就要三张一样的），和扑克炼金术的「不许重复」正相反。
提示区只有**手上这张 + 下一张**（`PREVIEW = 1`）。点空格放下、或把牌拖进空格。

**8 条消除线** = 3 行 + 3 列 + 2 条对角线，每条正好 3 张。三张凑成牌型即计分并整条消除（先闪烁两下再消失）：

| 牌型 | 分数 | 说明 |
| --- | --- | --- |
| 顺子 | 100 | 三张点数连续（1-2-3、7-8-9…）|
| 刻子 | 200 | 三张相同 |

**一次落子在多条线上都成牌型时全部计分，并从第二组起每组再加 100**（两组 +100、三组 +200，
见 `board.js` 的 `comboBonus(groups) = (groups-1) × 100`）。落子在中心格时最多同时过 4 条线。

**连击**：连续每次消除算一连，**从第二连起每连一次多 50 分**（`board.js` 的 `chainBonus(chain) = (chain-1) × 50`），
中间有一手没消掉就归零。得分浮字会多一行「🔥 连击 ×N」，奖励算进这次得分里、也参与特效档位判定。

**替换**：点一个**已经有牌**的格子，就用手上这张把它替换掉 —— 原来那张直接弃掉，同样消耗一张手牌
（`placeByClick` / `placeByDrag` 里都不再拦「格子非空」，`onCellClick` 的判空也去掉了）。
这条让棋盘放满不再是死局。

**失败**：只有「**牌用完了、分数还没到目标**」才算输（`loseReason = 'deck'`，文案「牌用完了」）。
棋盘满已经不是死局（可以替换），所以 `board.js` 的 `isStuck()` 不再参与判负，只作为纯函数留给测试用；
`overStuck` / `endlessOver` 两条文案也一并闲置。
**无尽模式**牌墙无限、又能替换，因此**没有判负条件**，一直玩到玩家自己点「新游戏」（最高分照常累计）。

**两种模式**（顶栏帮助图标旁的开关切换，各自独立记录）：

- **闯关**：牌堆有限，在牌用完前达到目标分即过关。
- **无尽**：牌墙无限、也没有结束条件（能替换就不会卡死），记录最高分；点「新游戏」**只清已用牌数与
  当前得分，最高分保留**。

**得分庆祝照抄扑克炼金术（也就是消消乐那一套）**：每次得分都在棋盘中央弹「牌型名 + 本次得分」
（多组时显示「连消 n 组」）；得分 ≥ 300（两组以上才够）再加棋盘震动 + 外圈闪光 + 撒花。
结算层只等这条浮字露一下脸就出现 —— `settle()` 延迟共用 `src/shared/resultDelay.js` 的 `RESULT_DELAY_MS`
（0.5s）后结算，不等浮字整条生命周期（那样要 1.32~1.76s，玩家能明显感觉到停顿）；`checkEnd()` 有
`phase !== PLAY` 提前返回防止重复撒花。这个时长是**参照消消乐**定的，它的 `winLevel()` 直接铺结算层、完全不等待。

## 关卡曲线与难度标定

`board.js` 的 `levelConfig(level)`：**第 1 关 20 张牌、400 分过关；之后每关 +2 张牌、过关分 +50，
逢 10 的整数关那一档的增量按 100 算**（`deck = 20 + (lv-1)×2`、`target = 400 + (lv-1)×50 + ⌊lv/10⌋×50`）。
实测第 2 关 22 张 / 450 分、第 9 关 36 张 / 800 分、**第 10 关 38 张 / 900 分**、第 20 关 58 张 / 1450 分。

离线标定（只看一步的贪心玩家，400 局/关；「含替换」指它也会点已有牌的格子去凑）：

| 关卡 | 牌数 | 目标分 | 贪心（会用替换）| 贪心（不替换）|
| --- | --- | --- | --- | --- |
| 1 | 20 | 400 | 98% | 50% |
| 2 | 22 | 450 | 95% | 38% |
| 5 | 28 | 600 | 99% | 35% |
| 10 | 38 | 900 | 99% | 22% |
| 20 | 58 | 1450 | 100% | 6% |

**关键结论：替换机制把难度整个掀翻了。** 不能替换时这条曲线的爬升很漂亮（50% → 6%），
但一旦会用替换，贪心的通过率直接飙到 95~100% —— 它每张牌都能找到「替换掉某格就成组」的下法，
中位数从 600 一路到 2200（第 20 关目标才 1450）。所以**这套数值对会用替换的玩家相当宽松**，
属于「前几关熟悉规则、后面靠连击和一次多组刷高分」的手感；以后要加难度，动的是每关的 +50 步长
（上表就是这个步长的标定依据）。和扑克炼金术一样，贪心是人类玩家的下界。

## 实现要点

- 纯逻辑在 `board.js`：8 条线、`evaluateLine`（刻子 > 顺子）、`scoringLines`、`comboBonus`（一次多组）、
  `chainBonus`（连击）、`createWall`（36 张洗牌、抽空重洗）、`levelConfig`；`isStuck` 还留着但**不再判负**（见上）。
- 麻将牌是**纯 CSS 画的**（`MahjongTile.vue`）：象牙白牌面 + **底部一条厚度**（`box-shadow` 的
  `0 Npx 0 <侧面色>`）+ 落地阴影，做出「正面偏下看过去」的立体感；尺寸由父级给 `--mj-w` / `--mj-h`
  （牌是 1 : 1.35 的竖牌，`board.js` 的 `TILE_RATIO`）。
  牌面的圆点排布与颜色都写在组件的 `LAYOUT` 表里（x / y 是牌面百分比，`c` / `cm` / `cc` 分别是外圈 / 中圈 / 中心的颜色，
  取值 `b` 蓝 / `g` 绿 / `r` 红；不写 `cm`、`cc` 就回落到 `c`，也就是单色点）：
  **一筒**一颗大圆、也是唯一的三色点（**红心 + 绿中圈 + 蓝外圈**）、**二筒**竖排（上蓝下绿）、
  **三筒**斜排（蓝 / 红 / 绿）、**四筒**四角（**绿在正对角线**：左上绿、右上蓝、左下蓝、右下绿）、
  **五筒**四角同四筒 + 红心、**六筒**上二绿 + 下四方四红、**七筒**上三绿斜排 + 下四方四红、
  **八筒**两列四行全蓝、**九筒**三行三列（上排蓝 / 中排红 / 下排绿）。
  **这一套是照着实物牌对照图逐张核对过的**（用户提供了一张九张牌并排的图，每张都切出来放大看过），
  不是凭印象配的：早先版本二筒上下颠倒、三筒全蓝、四/五筒绿在副对角、六筒画成 2×3、七筒方阵用蓝、
  八筒首尾两行红、九筒全蓝，全都与实物不符。三种颜色的色值在 `DOT_COLOR` 里，要微调只改这一处。
  **圆点大小按张数递减**（实物牌就是张数越少点越大，不是所有牌一样大）：`BASE_DOT = 0.24`（占牌宽比例）
  再乘一张按牌面的系数表 `DOT_SCALE = { 1: 2.0, 2: 1.6, 3: 1.35, 4: 1.15, 5: 1.08, 6: 1.02, 7: 0.98, 8: 0.98, 9: 0.98 }` ——
  实测点直径占牌宽 48% / 38% / 32% / 28% / 26% / 24%（六~九筒）。九筒的点位（`LAYOUT[9]`）特意往外撑到 23/50/77，
  否则点一大就贴在一起；七筒下方的方四同理。
  **圆点图案**按实物牌画：**中心一个实心圆点 + 中圈细线 + 外圈粗线** —— 用三层硬断点的 `radial-gradient`
  实现（`0~24%` 实心点、`40~52%` 细中圈、`68~100%` 粗外圈），三层颜色分别由 `--dot-core` / `--dot-mid` /
  `--dot` 三个变量给（后两个不设时回落到 `--dot`）。早期版本画反了（外圈实心 + 中间留白），不是实物牌的样子。
  **这里有个必须记住的坑：`radial-gradient` 一定要写 `circle closest-side`。** 默认尺寸是 `farthest-corner`
  （圆心到**角**），那是半径的 √2 ≈ 1.41 倍，于是所有百分比都被放大：最外那道 `68%~100%` 落到圆周上
  只剩 4% 半径宽，**外圈反而比中圈细**，看上去就是「内外搞反了」。实测（56px 直径的点，3× 截图逐像素扫描）：
  漏写时外圈蓝 1.3 CSS px / 中圈绿 4.7 px，加上 `closest-side` 后是外圈 9.3 px / 中圈 3.3 px，才符合实物牌的「外粗内细」。
  排查手法：把点放大截一张图，用 PIL 沿过圆心的水平线扫一遍颜色分段，直接量出每一道的像素宽度。
- 落子 / 替换 / 消除 / 庆祝 / 延迟结算 / 存档全部沿用扑克炼金术：点击格子先让浮牌从手牌位置飞到目标格
  （落点先隐身），拖拽则直接落子；被消的 3 张进 `clearing` 浮影层播 `blink-clear`。
  替换与落子走同一条路径（`commitPlacement` 直接覆盖该格），所以「飞行落点先隐身」对替换也成立 ——
  被换掉的那张在提交那一刻就从数据里没了，视觉上由飞进来的新牌接上。
- 连击数 `combo` 是局面的一部分，**跟着存档走**（`state.combo`），换关 / 新游戏时归零。
- 尺寸 `metrics`：宽度按 `min(innerWidth, 480) − 32 − 16` 反推，高度按
  `innerHeight − 262` 再按 1:1.35 回算，两者取小（格子上下限 56 ~ 132）；手牌固定 44×59，
  操作区仍是 `height: auto`（牌比 `var(--row-height)` 高）。
  **格子里那张牌的尺寸要按格子高算，不能只按格子宽**：牌是立体的，底部那条厚度（`0.075w`）画在
  元素外面，而格子又是居中排版（上下富余各一半），所以整体高度 `1.35w + 0.075w` 必须再连上下各留
  `0.075w` 才顶不出去 —— 即 `boardTileW = min(格宽, 格高 / (1.35 + 2×0.075)) = min(格宽, 格高 / 1.5)`，
  高度仍按 1:1.35 走（保住实物牌形状）。**第一版只按格宽算（牌 = 格宽 − 6），结果牌底厚度直接顶出格子**：
  实测修前是负余量，修后 320×568 / 390×844 / 480×900 三档的「牌面 + 厚度」距格底分别留 3.1 / 2.9 / 2.9px，
  左右留 5~9px、上方留 7~11px。
  **棋盘的底部内边距只补「牌底厚度」这一条**（`--lip = (格宽 − 6px) × 0.075`，实测 15.7px@390×844、
  12.5px@320×568）：格内牌已经按 1.5 倍格高缩进格子、实心部分本来就在格子里，所以底部只需要让
  **「牌面 + 底部厚度」这块视觉实体在棋盘里上下居中**（上边是 8px 内边距 + 格子内的居中留白，下边同理，
  再补上厚度）。对应的高度预算也从原来的量改成 `0.075w`（用宽度估出的格宽算，避免与真实 cw 循环依赖）。
  **这个值踩过一次**：最初为了容纳**落地阴影**（偏移 0.1w + 模糊 0.15w）按 `0.22 × 格宽` 留（约 32px），
  结果棋盘内边距变成「上 8 / 下 32」，底部比上边空出 24px、肉眼一看就不对称。改成只补厚度之后，
  柔和的投影允许越过棋盘边缘 —— 实测它反而也落在棋盘内（余 2px@390、6px@320）。
  实测上下视觉留白：390×844 是 18 / 19px，320×568 是 15 / 15px。

## 坑

1. **模板里用了没定义的变量，Vue 不报错、只是静默变 `undefined`**：手牌/预览的槽位尺寸写在
   `slotVars(handW)` 里，而脚本里定义的常量叫 `HAND_W` —— 结果 `width: undefinedpx`，**手牌和预览整块是空的**，
   控制台里只有一条 dev 警告（生产构建里连警告都没有）。棋盘能正常显示是因为它用的是 `cellW/cellH`。
   排查方式：量 `.current .mj` 的 `getBoundingClientRect()`，发现是 0 才知道尺寸没传进去。
2. **别只看「能跑」就以为改完了**：这一版第一次截图时手牌是空的，如果只跑「点击得分」的用例是发现不了的
   （棋盘、计分、庆祝都正常）—— 新游戏第一次打开必须**截图看一眼**。
3. **整页文字色漏了写**：`.wrapper` 第一版没写 `color: var(--text-color)`（其它 18 个游戏都写了），
   深色主题下标题与统计数字继承浏览器默认的黑色 —— 实测标题对比 1.39:1、数字 1.66:1，几乎看不见。
   现在 `App.vue` 的 `body` 加了全局兜底，本作也补上了这一句。**这类问题肉眼在浅色主题下完全看不出来**，
   靠「逐元素算前景/背景对比度」的脚本审计（20 路由 × 两套主题 × 每个带直接文字的元素）才定位到。
4. **立体效果要预留空间，而且要在「棋子所在的那一层」留**：牌的底部厚度与落地阴影都画在元素外面。
   这个坑我踩了两次 —— 第一次只给棋盘底部加了留白（牌仍然顶出**格子**），第二次才把牌按 1.5 倍格高
   缩进格子。教训：给带立体阴影的棋子定尺寸时，先问「它的视觉包围盒是谁的几倍」，
   然后从**最内层容器**（这里是格子）开始留，外卖的容器再额外留阴影量；
   CSS 的 `getBoundingClientRect()` 量不到 `box-shadow`，必须自己按偏移 + 模糊把包围盒算出来量。
5. 构建退出码被管道吃掉那个坑见扑克炼金术分册的「坑」第 6 条，同样适用于本作。

  右侧只有「🎮 新游戏」（走共用 `ConfirmDialog`，无尽模式隐藏「重玩本关」）。
- 棋盘是 9 个常驻网格格位（描边 + 半透明底），牌嵌在格位里四周各留 3px；手上有牌可放时空格子换成主色虚线
  （`.placeable`），**已经有牌的格子**加 `.actable`：鼠标悬停时套一圈主色描边，提示「点它会被替换」。
- 得分浮字 `.celebrate` 绝对定位在 `.game-area` 正中，主色底 + 白字，`celebrate-pop` 0.95s 播完即消失；
  连击时中间多一行 `.celebrate-chain`（「🔥 连击 ×N」，13px）。
- 棋盘套 `.dot-board`（点阵底纹来自 `App.vue` 的全局类，别再写 `background: var(--board-bg)`）。

## 候选区与格子高亮（本轮补充）

- **候选区主次**：当前牌 `.tile-slot.current .mj` 套一圈主色描边（`outline: 2px solid var(--primary-bg)`，
  `outline-offset: 1px`），下一张 `.preview` 压到 `opacity: 0.55`；缩放 `PREVIEW_SCALE = 0.8`
  （实测渲染宽 44 → 35）。
- **牌在格子里的垂直居中**：`boardTileW = min(格宽, 格高/1.5)` 只保证「牌面 + 厚度」塞得进格子，
  但格子是居中排版、厚度画在元素外面，所以整块会**贴住下边缘**（实测上 7.25px / 下 0.15px）。
  补一条 `.board .cell .mj { margin-bottom: calc(var(--mj-w) * 0.075) }`：flex 居中会把元素上移
  「下外边距的一半」，正好等于厚度的一半，整块就回正了 —— 实测 6.47 / 6.48px，左右 7.5 / 7.5px。
- **点击格子给实线高亮**：`onCellClick` 里记 `flashCell` + 450ms 后自动清掉（计时器 `cellFlashTimer`，
  注意别和庆祝闪光用的 `flashTimer` 撞名），`.cell.flash` 换实线主色 + 光环。
- **特异性坑同炼金术**：基础规则编译成 `.wrapper .game-area .board .cell[data-v]`（0,5,0），
  所以 `.flash` 必须写成 `.wrapper .game-area .board .cell.flash`，只写 `.board .cell.flash` 会被
  基础那条 `border: 1px solid var(--tile-border-color)` 压掉，表现为「光环出来了、边框色没变」。
