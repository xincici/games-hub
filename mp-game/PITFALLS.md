# 小游戏迁移踩坑记录

> 用途：迁移下一个游戏之前先扫一遍；每个迁移任务结束时，把新踩到的坑追加到对应章节。
> 原则：**先记录症状，再记录根因和修法，最后写成以后不能违反的规则。**

## 一、Canvas / 图标 / 资产

### 1. 所有 icon font 图标看起来偏左

- **症状**：首页、home、help 等 UnoCSS / Iconify 图标整体偏左。
- **根因**：生成 TTF 时的横向平移只按 `(EM - glyphSize) / 2` 计算，没有按真实墨迹框 / em box 中心处理；不同端对 `textAlign='center'` 的实现也不完全一致。
- **修法**：`icons.draw()` 优先用 `measureText()` 的 `actualBoundingBoxLeft/Right` 把真实墨迹框居中；不支持时退回 advance 宽度。
- **规则**：所有单色图标只走 `icons.draw()`，不要在各场景手写 `fillText` 或重新算字体居中。

### 2. 首页 2048 图标显示成文字 / 图标缺失

- **症状**：某些新加 glyph 没有画出来，落到了文字 fallback。
- **根因**：字体缓存 / glyph 构建或 key 映射不一致。
- **修法**：确认 `build-icons.py` manifest、`icon-glyphs.js`、`HomeScene` 的 `glyphs` map 三处 key 完全一致；必要时用已稳定的 `calculator` glyph 兜底。
- **规则**：新增首页图标必须同时更新构建脚本、生成文件和首页映射；改完重新生成 TTF，不能只改场景。

### 3. 真机麻将牌变成 `Z2 / M3` 文字

- **症状**：模拟器正常，发布到真机后麻将牌是文字降级。
- **根因**：雪碧图使用 WebP，部分真机 canvas 对 WebP `drawImage` 支持不稳。
- **修法**：构建时转成 `images/mahjong-tiles.png`，启动时 `tiles.preload()`；加载失败才用文字降级。
- **规则**：牌面图片只用 PNG；`game.js` 启动预加载。

### 4. 麻将牌边框 / 圆角不对

- **症状**：牌面多一圈米色边框，或四角露出灰色方角。
- **根因**：雪碧图本身带底色和描边，外面又套了一层圆角底 / 1px 边框；同时 PNG 没有透明圆角，直接 `drawImage` 会带出方角。
- **修法**：先按统一 8px 圆角 `clip()`，再直接画雪碧图；**不要再套第二层边框**。
- **规则**：所有牌面统一走 `core/cards.js`；麻将正面 = 8px clip + 原图，背面 = 绿色斜纹 + 8px。

### 5. emoji 卡片大小 / 垂直位置不统一

- **症状**：连连看的 emoji 明显比对对碰 / 侦探大，而且位置偏上。
- **根因**：连连看自己按 `cell * 0.66` 画 emoji，并直接按 `middle` 基线；其他游戏走 `cards.draw`，比例是 `w * 0.42`。
- **修法**：所有 emoji 牌统一走 `core/cards.js` 的 `drawEmoji()`；尺寸统一 `w * 0.42`；优先用 `actualBoundingBoxAscent/Descent` 做墨迹垂直居中，再统一补 `0.30em` 视觉上浮偏移；不支持 actualBoundingBox 时退回 `middle` 基线。
- **规则**：emoji 卡片不允许各游戏自定字号和基线；空白格不画卡片，只有有牌的格子画。

### 5. 各游戏牌面各画一套，样式漂移

- **症状**：对对碰、侦探、猎手、消除大师的扑克 / 麻将 / 牌背不一致。
- **修法**：删除对对碰私有 `drawPoker/drawBack/drawMahjong`，全部走 `cards.draw()`；统一圆角 8、牌背、比例。
- **规则**：新游戏不允许写私有牌面；新牌面类型先扩展 `core/cards.js`。

## 二、布局 / 首页 / 弹层

### 6. 首页两行蜂窝垂直间距太大

- **症状**：上下行像两块独立网格，缝隙明显大于水平缝隙。
- **根因**：两行按 `2r + gap` 排，没有做蜂巢咬合。
- **修法**：行中心距离 = `2r - overlap`，`overlap = W * 40 / 750`（小程序 `-40rpx` 口径）；多行用 `step = 2r - overlap` 连续排。
- **规则**：首页蜂窝行间必须负 overlap 咬合，不能按普通 flex 间距堆叠。

### 7. 首页游戏名压图标 / 图标太小

- **修法**：7 格时 icon 区域 30、glyph 25；游戏名 12；新增到 25 格后用 4+3+4+3+4+3+4，保持行数奇偶交替。
- **规则**：增加游戏先算行数和卡片宽度，再调 icon / 字号，不要直接复制单行尺寸。

### 8. 设置抽屉 / 底部输入区离屏幕底部有缝

- **症状**：抽屉或 1A2B 键盘下面有一条背景色。
- **修法**：面板总高包含 `SAFE_BOTTOM`，底边贴屏幕底，安全区作为**内部 padding**；footer 文案放在安全区之上。
- **规则**：吸底面板不要用 `H - SAFE_BOTTOM` 当底边。

### 9. 结算遮罩重进后错位

- **症状**：退出重进侦探 / 猎手，胜负遮罩、牌面、按钮全部歪掉。
- **根因**：恢复 `level / board / phase` 后没有重新 `layout()`，仍沿用旧关卡的坐标。
- **修法**：restore 成功后立即 `layout()`；猎手遮罩只覆盖候选区，不盖上方目标区。
- **规则**：任何恢复局面的场景，restore 末尾必须重新布局；遮罩范围要按游戏区 rect 计算，不要用整个页面。

### 10. 胜负时底部 FAB 消失

- **修法**：渲染条件只排除 help / confirm，不再排除 WON / LOST / over。
- **规则**：结算层出现时，帮助和模式 FAB 继续显示。

## 三、转场 / 输入

### 11. 进入 / 退出游戏没有过渡

- **修法**：`App.openGame(id, origin)` / `goHome()` 用离屏 canvas 给旧场景拍快照；进游戏从卡片中心 `scale(0.08)→1`，回首页 `1→0.08`，320ms。
- **规则**：游戏内 home 一律 `app.goHome()`；不要直接 `openScene(home)`，否则没有收起动画。拿不到第二块 canvas 时退回即时切换，不能崩。

### 12. 弹窗按钮点不到 / 点穿

- **修法**：先加全屏 mask，再加面板按钮；`Input.find()` 从后往前扫描，后加的面板按钮优先。
- **规则**：所有 modal 的 mask 必须先 addButton，面板按钮后 addButton。

### 13. 过渡期间误触

- **修法**：`drawTransition()` 渲染时 `input.setButtons([])`，动画结束下一帧恢复正常。
- **规则**：场景切换 / 全屏转场期间不接收操作。

## 四、游戏逻辑 / 存档

### 14. 2048

- 分数是**盘面最大牌**，不是累计合并分。
- 存档的 `WIN` 恢复成 `GAMING`；`winShown` 保留，避免重复胜利。
- 新游戏直接开始，没有二次确认。
- 两阶段移动：先按 id 换格，130ms 后删掉被合并的两张、加一张新 id 的合并牌，再补新牌；不要用 ghost 隐形标记，容易永久消失。
- 合并弹跳 / 新牌缩放的 scale 必须在动画结束后回到 1，不能停在 1.16 / 1.1。

### 15. Threes

- 每张牌每次最多走一格，不是 2048 式滑到最远。
- 1+2=3，3 以上同数翻倍；1+1 / 2+2 不合并。
- 每张牌每步最多合并一次（`ahead.mergedThisStep`）。
- 得分 = 盘面所有牌分值之和，1/2 为 0。
- 1/2 牌堆平衡差 ≤ 4；`next` 预览也要一起存档。
- 新游戏打断旧的 140ms 落定回调，避免旧回调覆盖新盘。

### 16. 贪吃蛇

- 撞墙 / 撞自己都在 `unshift` 前判断；尾巴格也算身体。
- 默认穿墙，`__snake_game__through_wall` 只显式存 `'0'` 才关闭。
- 恢复进行中存档默认暂停，恢复失败存档保持失败且**不要播 lose**。
- 满盘时 `spawnFood` 要允许 `null`；`tick` 要判空。
- 暂停恢复要 3-2-1 冻结倒数，不能一按就继续。

### 17. 连连看

- board.js 用 `null` 表示空格，墙既挡连线路也挡放牌；棋盘外一圈是空的。
- `findPath` 最多 2 转折；路径可走到 `-1 / H / W` 外圈。
- 消除后如果无解，先 `shuffleBoard`，仍无解再 `generateBoard`；不能只洗牌。
- 新游戏二次确认；重玩本关不清最高关。
- emoji **保留卡片底**，但空白格 / 墙格不能画卡片底；墙用斜纹块；连线用 halo + 细线；外圈线在棋盘边缘外 0.14 格，首尾缩进 0.42 格。
- 消除时牌先闪烁（最多两次），闪烁结束再把两张牌和连线**同时**抹掉；不要在点击瞬间先清空 board。
- 棋盘起点 / 28px 提示带 / 连击 chip 位置对齐对对碰；连击小烟花和胜利礼炮都要有。
- 连击 2.5s 窗口，非消除点击要打断。

### 18. 消除大师

- 三种模式的 `mode / level / state` 全部独立；切模式前保存当前状态，切回恢复。
- 状态必须实时保存（拿牌、三消、失败、胜利、切后台），不能只保存胜利。
- 恢复时恢复 tiles/tray/level/phase；`tileId` 接续最大 id，避免新 id 冲突。
- 暂存槽形状跟牌面走：emoji 1:1、扑克 2:3、麻将 131:168；槽底、飞行卡、消除卡共用同一个 rect。
- 初始化逐张入场、飞入槽位、三消闪烁都要有；飞行目标用 slotRect，不能写死正方形。

### 19. 侦探 / 猎手

- 观察倒计时用沙漏，作答已用时间用秒表。
- 进入 ANSWER 前：目标牌翻回背面，候选区同时翻正；找回目标后对应目标牌再翻正。
- 猎手的胜负遮罩只盖候选区，保留上方目标区。
- 恢复结算后必须重新布局（见第 9 条）。

### 20. 全部模式的共同存档规则

- key 与 web / 小程序一致，不要改名。
- 恢复只接受结构合法的状态；字段 id / emoji / 坐标 / 关卡要校验。
- 结算局面可以恢复，但恢复时不要重播烟花 / 音效。
- 分享 / 切换模式 / 退出前先落档。

## 五、计时器 / 控件

### 21. 计时器图标不统一

- **规则**：正计时一律秒表 `stopwatch`，倒计时一律沙漏 `hourglass`，统一走 `core/timer.js` 的 `drawTimer()`。
- 目前：2048 / Threes / 1A2B 已用时间 → 秒表；Match / Link 限时、侦探 / 猎手观察 → 沙漏；侦探 / 猎手作答时间 → 秒表。
- 不要再用 `⏳` / `⏱` 文本当计时图标。

### 22. 难度步进器样式不统一

- **规则**：参考关灯游戏：28×28 描边小按钮、8px 圆角、数字 18px 加粗、点击热区外扩 8px、三格布局 30% / 65% 分隔。
- Snake 已对齐；后续有 `− n +` 的区域直接复用这套参数。

## 六、动画 / 撒花

### 23. 配对闪烁次数太多

- **规则**：所有配对 / 消除闪烁统一用 `core/motion.js` 的 `matchedMotion(age)`：最多两次明暗循环；不要按固定 80ms 硬切。

### 24. 撒花过度集中 / 落在两侧

- **规则**：左右礼炮，目标带 `center ± W*0.28`，越过中线后收住水平速度，只保留重力；不要回到单点喷发或只落两侧。

### 25. 动画 scale 不归位

- 合并 / 新牌 / 闪烁的 scale 必须按时间 clamp 到 1；动画结束后不能停在放大值。

### 26. 首页所有游戏都用同一个绿色

- **症状**：首页边框和图标全是主色，分类感丢失。
- **修法**：按 web / 小程序的 accent 分类上色：logic #23804e、number #2c6aad、memory #7550ad、action #bd5420、card #8f6419；六边形外层用 18% 混色（#abc2c1 / #adbed2 / #bab9d2 / #c7bab9 / #bfbdb7），图标用完整 accent。
- **规则**：新增首页游戏必须同时给 `accent`，不能默认主色；首页布局按 4/3/4/3… 动态分行。

### 27. Emoji 镜像恢复局面时展示区和游戏区数量不一致

- **症状**：恢复存档后 rows / 卡牌错位，或游戏区出现空位。
- **根因**：只校验了 `display.length` 和“当前难度”其中一个，条件写反时另一种情况会漏过。
- **修法**：先按 `saved.difficulty` 算出 expected，再要求 `display.length === expected && game.length === expected`；恢复后重新 layout。
- **规则**：镜像展示区和游戏区必须同长度、同样行数；开局 `derange` 保证零匹配，游戏区在展示阶段保持背面。

### 28. Emoji 下坠牌堆被消除后出现空档 / 越界

- **症状**：消掉顶排后底部空出一条，或堆被推出棋盘。
- **根因**：只 `shift()` 没有补底，或 `top` 没有钳在合法范围。
- **修法**：`clearRow` 后 `top = min(ROWS-1, top+1)`，立即 `fillPile()`；每一帧上升后也 `fillPile()`；`top - 1 <= 0` 判负。
- **规则**：牌堆必须始终从顶排连续铺到棋盘底，不能有空档；点列只移动玩家列，不改变牌堆结构。

### 29. 数字迷宫洗出不存在的局面

- **症状**：滑块局无解。
- **修法**：从完成态开始随机走合法相邻步，保证可解；不要直接 `shuffle` 数字。
- **规则**：滑块类游戏只从完成态打乱。

### 30. Emoji 镜像没有动画

- **症状**：展示区一出现就是最终状态，交换也没有移动，整个游戏像静态表格。
- **修法**：按阶段推进：`REVEAL`（展示 1.2s）→ 逐张 `FLIP_DOWN` → `GATHER` 聚到展示区中心 → `FLY_BACK` 飞回 → 逐张 `GAME_FLIP` 翻正 → `PLAY`。交换用 300ms 两张牌对向位移，位移结束后再交换数据并进入 450ms `CHECK`。
- **规则**：镜像的展示、洗牌、翻面、交换都必须有过渡；不要直接把 phase 置为 PLAY。
- **补充坑**：`startRound()` 里曾把 `displayFlips / gameFlips / displayOffsets` 重置成空数组，渲染时取不到值就 fallback 成正面 / 无位移，看起来完全没有动画。每开一局必须按新 `round.display.length` 重新填满这些数组。

### 31. 动画字段加了但忘了在 update 清理

- **症状**：数字迷宫点一次后所有数字都不再响应，移动中的牌一直停着。
- **根因**：`onCell` 设置了 `moveAnim`，但 `scene` 根本没有 `update(dt)`，没人把动画状态清掉。
- **修法**：所有动画字段都必须有对应的 `update` 推进 / 到期清理；新增动画后检查 `this.xxxAnim` 是否会在 140~350ms 后归零。
- **规则**：不能只在 render 里读动画时间，必须有 update 生命周期。

### 32. 打开帮助后游戏还在跑

- **症状**：看帮助时贪吃蛇仍在移动、计时器仍在涨、侦探观察阶段继续跳转。
- **修法**：`update()` 在 `helpOpen || confirming` 时直接返回（或冻结计时/定时器）；关闭后再继续。
- **规则**：所有 modal 打开期间冻结游戏逻辑，不能只画遮罩。

### 33. 恢复镜像存档时展示区被翻开

- **症状**：退出重进后本应藏起来的展示区直接显示答案。
- **根因**：restore 把所有 flips 初始化成 1。
- **修法**：PLAY 恢复时展示区 flips 为 0、游戏区为 1；只有 WON 才让展示区翻开。
- **规则**：恢复状态必须按 phase 决定牌面朝向，不能一律正面。

### 34. 对对碰配对闪烁时整盘锁死

- **症状**：消掉一对后，闪烁还没结束，点其它牌完全没反应。
- **根因**：配对成功时把全局 `lock` 设为 true，等 470ms 后才在 `resolveMatch` 释放；这段时间所有牌都被拦住。
- **修法**：配对成功立即把两张标记为 `matched` 并启动闪烁，不设置全局 lock；只让不匹配的翻回动画使用 lock。这样其它未翻牌可以在闪烁期间继续操作。
- **规则**：动画期间的输入锁只锁“同一对牌”，不要锁整盘；匹配牌本身通过 `matched` 排除点击。
- **同类**：Emoji 连连看也曾用 `pendingClear` 在 520ms 闪烁期间拦住 `onCell`，导致其它牌不能点。修法是：逻辑上立刻把两张牌置空，渲染层保留一组 `clears` ghost + 连线做闪烁，结束再移除 ghost；其它牌继续可点，路径自然绕开已置空的位置。后续任何消除动画都按这个模式做。

### 35. 24 点算式偏右、禁用符号不明显

- **症状**：算式整体偏右；不能点的 + − × ÷ 和可点状态几乎一样。
- **根因**：算式左侧预留了 34px，右侧又给退格留空间，导致可用区域中心偏右；操作符底板不管 enabled 都用浅色 enter。
- **修法**：算式按卡片中心 `W/2` 居中，最大宽度对称扣掉退格区域；操作符可点用白底 + 主色描边 + 主色字，不可点用 `T.disabled` 灰底 + 灰字。
- **规则**：带右侧工具按钮的居中文本，按整体中心排版，不要一边多留空白；禁用态必须换底色，不能只换文字颜色。

### 36. Threes 只做松手滑动，没有跟手和 95% 提前提交

- **症状**：滑动时牌不动，必须松手才动；拖到 90% 松手也没有合并，像普通 swipe。
- **参考行为**：Slop 10px 锁定方向；只让本步会移动的牌跟随手指；拖动超过 50% 松手提交，超过 95% 直接提交；不足 50% 弹回。
- **修法**：`onTouchStart/Move/End` 维护方向锁、movers、dist；渲染时只给 movers 加 `dir * dist` 偏移；提交后再走原有 130ms 落定 / 合并。
- **规则**：Threes 不能只做 swipe-only；以后类似“跟手滑动 + 松手提交”的游戏统一用这个 10px / 50% / 95% 参数。

### 37. 游戏卡片分隔线太长

- **症状**：分数卡 / 操作卡里的竖分隔线几乎顶到卡片上下边，和缩小的分栏内容不协调。
- **参考**：小程序 `.divider` 高度为 48rpx（约 24px），垂直居中；不是 `卡片高 - 28`。
- **修法**：统一用 `core/draw.js` 的 `D.divider(c, x, centerY, 24, color, 1)`；分数卡按 `scoreY + scoreH/2`，操作卡按 `optY + optH/2`。
- **规则**：以后所有游戏卡片内分隔线固定 24px 高、垂直居中；不要再按卡片上下内边距自动撑满。

### 38. 分数卡进度条戳出卡片圆角

- **症状**：带进度条的分数卡，底部横条两端是直角，和 14px 圆角卡片不协调。
- **根因**：进度条直接 `fillRect` 卡片全宽，没有裁切到卡片的圆角路径。
- **修法**：用 `core/draw.js` 的 `D.progressBar(...)`：先按卡片 14px 圆角 `clip()`，再画轨道和进度；禁止直接画满宽横条。
- **规则**：以后所有贴在卡片边缘的进度 / 高亮条都必须先裁到卡片圆角。

### 39. 镜像操作区不等分 / 洗牌没有重叠散开

- **症状**：难度区只占卡片左侧约 30%，新游戏按钮很宽；洗牌时牌像平移回原位，没有“叠起来再散开”的感觉。
- **修法**：难度步进器和「新游戏」各占操作卡 50%；洗牌阶段拆成 `GATHER`（叠到中心）→ `STACK`（重叠停留 240ms）→ `FLY_BACK`（随机延迟散射回各自位置）→ `GAME_FLIP`。
- **规则**：镜像操作区和其它双栏操作卡保持等分；洗牌不能只做同速直线归位，必须有重叠停顿和错峰散开。

### 40. 初始化 / 恢复动画没有按左上到右下依次出现

- **症状**：数字迷宫开局所有数字同时弹出；其它游戏候补牌有些是斜线波浪、有些按数组随机顺序。
- **规范**：所有开局 / 恢复时需要入场的卡片、数字、牌面，统一按**行优先 index** 错峰：`index = row * cols + col`，每格约 20~45ms，先左上后右下。
- **不要**用 `row + col` 做斜线波浪，也不要按 shuffle 后的数组顺序。
- **修法**：先算 row-major rank，再给每张牌/数字赋 `dealAt / delay`；恢复时如果需要播入场动画，同样按这个顺序。
- **操作区**：双栏操作卡（难度 + 新游戏）默认 **50 / 50 等分**，不要一边 30% 一边 70%。数字迷宫已改为等分。

### 41. 难度 `− 数字 +` 被拉到两端

- **症状**：数字迷宫 / Emoji 镜像的操作区里，减号贴最左、加号贴分隔线，数字悬在中间，三个元素之间空隙很大。
- **修法**：把 `− 数字 +` 作为一个整体组，按 `28 + 12 + 数字宽 + 12 + 28` 计算组宽，在左半区居中；不要分别用左右边距定位。
- **规则**：所有难度步进器都按“组内紧挨、整组居中”布局，不能两端对齐。

### 42. 恢复存档播放入场动画时用了不存在的尺寸字段

- **症状**：Threes 恢复后 `dealing` 永远不清，或动画延迟为 NaN。
- **根因**：`restore()` 里写了 `this.n * this.n`，但 Threes 没有 `this.n`，实际常量是 `SIZE`。
- **修法**：恢复入场动画用实际存在的 `SIZE / rows / cols`；如果场景没有某个字段，不要照着其它游戏复制。
- **规则**：restore 分支也要跑类型 / 字段自检，动画时间不能出现 NaN。

### 43. 消除大师没有按层入场

- **症状**：开局 / 恢复时牌面同时出现，或先按行坐标出现，底层牌压在上面才出现。
- **参考**：从最下层开始逐层往上，每层内再按 `x/y` 左上到右下。
- **修法**：`prepareDeal()` 按 `layer → y → x` 排序生成 `dealOrder`；每张延迟 `rank * 25ms`，`restore()` 也要调用。
- **规则**：分层堆叠类游戏的入场顺序以 layer 为第一关键字，不能只按平面坐标。

### 44. 选对 / 选错只换边框颜色

- **症状**：侦探 / 猎手选错只是变红，选对只是变绿，缺少动作反馈。
- **修法**：抽 `core/fx.js`：选错 `wrongShake(age)`（350ms、±4px、幅度衰减）；选对 `popScale(age)`（450ms 一次性：1 → 1.18 → 0.96 → 1.04 → 1）。
- **接入**：侦探的错误牌晃动、正确牌弹一下；猎手的错误候选晃动、找回的候选弹一下；边框颜色保留作为静态状态。
- **规则**：正确 / 错误反馈不能只靠颜色；选对是一次性 pop，不是持续呼吸循环。

### 45. 选错音效和失败音效混用

- **症状**：侦探 / 猎手点错时直接播 `lose`，和整局失败听起来一样，扣心没有独立反馈。
- **参考**：小程序选错播 `fail.mp3`，整局失败才播 `lose.mp3`。
- **修法**：`core/audio.js` 增加 `playFail()` 和 `audio/fail.mp3`；选错（扣❤️）用 `playFail`，`hearts <= 0` / 结算失败再用 `playLose`。
- **规则**：`fail` = 单次操作错误，`lose` = 整局失败，不能互换。

### 46. 胜利烟花又紧又规律

- **症状**：碎片都从两侧固定高度、固定速度飞向屏幕中线附近，大小/形状几乎一样，看起来像两束整齐的粒子。
- **修法**：统一用 `core/confetti.js`：
  - 落点 `targetX` 在 10%~90% 屏宽随机，不再全挤在中线；
  - 起点 y 在较大范围抖动；
  - 初速度、重力、旋转速度随机；
  - 形状随机 rect / circle / ribbon / triangle；
  - 尺寸 3~10px 随机。
- **规则**：所有游戏胜利烟花统一走 `confetti.spawn/update/draw`，不要在各场景复制固定 5 颗、固定目标的版本。

### 47. 真机图标偏左、emoji 偏下

- **图标偏左**：真机 canvas 对自定义 icon font 的 `actualBoundingBoxLeft/Right` + `textAlign` 组合不可靠，按墨迹框算出来的中心仍会左偏。
  - 修法：`icons.draw` 用离屏 canvas 画一次 glyph，扫描 alpha 得到真实墨迹左右边界，缓存每个 glyph+size 的居中偏移；探针不可用时再退回中心对齐。
- **emoji 偏下**：`drawEmoji` 之前统一加 `0.30em` 的光学下移，真机上会过度下沉。
  - 修法：收到 `0.18em`，仍保留 actualBoundingBox 的垂直墨迹居中。
- **规则**：真机居中不要只信 measureText；icon font 用像素墨迹探针，emoji 用较小的光学偏移。

### 48. Threes 松手后先回原位再播放移动

- **症状**：拖动跟手到 50%~95% 松手，牌先跳回原来的格子，再重新播放一次移动动画。
- **根因**：`move()` 的 `fromRow/fromCol` 用的是拖动前的整数行列；松手时把 `drag` 清空，渲染先回到出发点，再开始补间。
- **修法**：`move(dir, startDist)` 接收松手距离，把移动牌的起点设为 `before + dir * (startDist / pitch)` 的**小数坐标**，动画从当前手指位置直接接到目标格。
- **规则**：所有跟手拖拽 + 松手提交的动画，补间起点必须是当前拖动位置，不能回到原格再播。

### 49. 首页加到第 6 行后顶部顶到副标题

- **症状**：25 格（4+3+4+3+4+3+4）七行下，375×667 上第一行六边形会顶到 `homeSubtitle`。
- **修法**：蜂窝中心下移到 `H * 0.51`（限制在 `H - 190`）；7 行布局需要按「标题下沿到齿轮上沿」的竖向预算反算半径；375×667 顶部约 98px、390×844 约 141px。
- **规则**：首页增行后必须同时检查 375×667 和 390×844 的顶部/底部/FAB 三处边界。

### 50. 数独数字键盘和右下 FAB 重叠

- **症状**：数独键盘铺在底部后，帮助 / 候选 FAB 直接压在数字键或工具键上。
- **修法**：不要只挪 FAB 的 y 让它覆盖键盘；在键盘上方单独留一条 40px 的 action row（右对齐，左边放难度名），棋盘底 = action row 上方 8px，键盘再下方。375×667 上棋盘缩到约 277px，390×844 上约 358px。
- **规则**：底部有整块键盘 / 按钮行时，FAB 必须独占一行或放到标题栏，不能覆盖可点区域。

### 51. 交互细节回归（本轮）

- **镜像**：交换后必须显示“计算中…”转圈，`CHECK_MS = 500`，结束后才显示对齐数；不能交换完立刻显示结果。
- **数字迷宫**：除点击外必须有滑动方向操作；滑动目标按空白格反方向取邻格。
- **下坠**：点击换列先走 150ms 横移动画，落位后再判消除；消行后旧行 180ms 下落，落定后若新顶排与手中 emoji 相同直接连锁；顶排 220ms 膨胀淡出。
- **连连看**：无可消对先显示 0.65s 提示，再洗牌；洗牌时牌面缩小/旋转/错峰恢复，不能瞬间换盘。
- **1A2B**：机器人 / 帮助 FAB 与退格/提交行垂直居中，键盘底部只留 10px，不能贴屏幕底。
- **猎手**：目标区找到后的绿色提示只描边，不要用半透明色块盖在牌面上（会把翻正的 emoji 压到背景层）。
- **消消乐 / 排序 / 滑行图标**：必须用小程序首页同款 `star-four-points` / `test-tube` / `arrow-all`，不要用近似图标。

### 52. 数独圆角 / 候选模式 / 难度文案

- **圆角被盖**：棋盘外层圆角填完后，内层仍用 `fillRect`，会盖掉外框四角的圆角。外框和内层都必须 `fillRoundRect`，内层半径 = `boardR - frame`。
- **候选模式**：不要保留“先切换候选模式、再逐格填候选”的交互；`候选` 按钮就是一次性填满所有空格的全部候选。笔记仍可保留为独立手动标记。
- **帮助位置**：帮助 FAB 保持在右下角老位置；键盘工具行右侧预留 48px，不要为了避让把 FAB 挪到键盘上方。
- **难度文案**：`− 简单/中等/困难 +` 的文案放在两按钮中间，不要单独占一行或只显示数字。

### 53. Emoji 排序点不动 / 背面图标不对

- **排序点不动**：`metrics` 漏了 `cell` 和 `headH`，槽位点击热区高度变成 `NaN`，Input 永远命中不了。补 `cell/headH`，热区高度直接用 `boardH - PAD`。
- **背面图标**：只要有扣着的 emoji 牌，牌背必须使用该游戏在首页的 icon，不能统一用灯泡：
  - 对对碰 `bulb`；侦探 `incognito`；猎手 `target`；消除大师 `layers`；镜像 `mirror`；排序 `sort`（试管的 Iconify glyph）。
  - 通过 `cards.draw(..., faceUp, backIcon, backFallback)` 传入；`cards.drawBack` 默认仍是 bulb，只给没传的老场景兜底。
- **检查范围**：所有 `cards.draw(..., false)` / `faceUp` 可能为 false 的 emoji 场景；扑克 / 麻将牌背仍走各自牌背，不受这条影响。

### 54. 数独操作区 / 帮助 / 工具图标

- **难度组溢出**：`− 6px 难度名 6px +`，按钮 24px；不要再沿用 28px + 10px 的宽组，左三分之一放不下。
- **固定间距**：棋盘顶边距操作卡 12px；操作区顶边距棋盘底边 12px；只缩棋盘，不把棋盘/键盘在剩余空间里居中。
- **操作区全宽**：操作卡宽度必须与上方卡片一致；不要为了给帮助按钮让位而缩窄。
- **帮助不侵入**：键盘下方预留 56px（40px 帮助按钮 + 8px 间隙），帮助 FAB 放在操作卡下方、不压键盘/工具行。
- **工具图标**：参考小程序 `format-list-numbered` / `pencil-outline` / `backspace-outline`；图标和文字作为整体居中，间距 5px，不能图标靠左、文字单独居中。候选主色、笔记蓝紫、擦除红色。

### 55. 镜像洗牌不流畅

- **症状**：聚拢末尾有轻微跳动，飞出瞬间卡片从 0.82 缩放突然跳到 1，个别牌像卡一下。
- **修法**：不要逐帧指数插值；用阶段时间做 easeOut：
  - `GATHER`：从当前位置到中心，420ms；
  - `STACK`：位移精确锁定中心，缩放 0.82；
  - `FLY_BACK`：每张按 90ms 错峰，位移和缩放（0.82→1）一起缓动；
  - 飞出结束一帧把位移归零、缩放归 1，再进入 GAME_FLIP。
- **规则**：洗牌类动画必须时间驱动、缩放与位移同步，动画结束显式归位。

### 56. 25 格首页与后续新游戏

- 首页 25 格用 `4+3+4+3+4+3+4` 七行；半径同时受宽度和竖向预算约束，375×667 顶部约 98px、390×844 约 141px。
- 扑克牌背用 `mode-poker`，图标尺寸 `max(16, w*0.60)`（旧 0.34 太小）；麻将英雄 / 单人麻将 tile 背面走麻将纹理，不要套 emoji 规则。
- 新游戏注册后必须同步 `js/games/index.js`、`game.js`、`GAME.js` 三处；首页卡片、icon、accent、i18n 四处。
- 扑克 5 张牌、麻将 3×3、单人麻将 14 张手牌/牌墙都必须用 `cards.draw`，不要另写牌面。

### 57. 结算遮罩 / 心形标签 / 返回键图标

- **遮罩太快**：新打出的 WON/LOSE 遮罩统一走 `Scene.resultVisible(250)`；先让最后一帧动画（翻牌 / 消除 / 落子）播完，再等 250ms。不要直接 `phase=WON` 后立刻铺遮罩。
- **恢复例外**：退出重进时如果场景第一帧就是结算态，`_hasRendered=false`，`resultVisible()` 立即放行，不能补 250ms。
- **心形旁小方格**：生命标签不要再写 `❤️ Lives` / `❤️ 生命`，生命图标单独画；文案里也不要混 `❤️`，避免真机 VS16 变方块。已清理侦探 / 猎手 / 数独。
- **1A2B 退格**：图标和“退格”文字必须作为一组居中，间距 5px；不能图标靠左、文字单独居中。
- **下坠消行**：只让玩家牌下落，下方已经存在的行位置保持不动；不要给整排加 fallOffset。
- **蛇暂停/继续**：与下坠统一为橙色实心 + 白字，不可点击时灰色实心；继续文案带 ▶，按钮宽度按文案 `min(cw/3 - 16, max(80, measure+22))` 动态计算，不要定宽。

### 58. 德州扑克区域顺序 / 猜大小 FAB / 牌型遮罩

- **中牌遮罩**：只覆盖牌型区，透明度约 0.95；牌型名 + 倍数 + 仅遮罩内的小烟花，**不要**启动全屏胜利礼炮。

### 102. 手动主题切换不触发游戏场景 `onTheme`

- 小游戏版本的系统主题由 `wx.onThemeChange` 触发，但设置抽屉里手动选择 light / dark 只改 `theme.mode`；只改状态会导致当前场景继续沿用旧 token，回首页或重进游戏才恢复。
- 修法是 `theme.refresh()` 切 token 后通知当前场景 `onTheme()`；`App` 只挂一份 `theme.onChange` / `i18n.onChange`，不要让每个场景重复注册。
- **规则**：所有主题 / 语言相关变化都必须通过当前场景的 `onTheme()` 重排 / 重绘；游戏内后续新增主题相关缓存量时，也要在 `onTheme()` 里重算。

### 104. 1A2B 记录区的规则提示从一行变两行

- **需求**：记录区顶部再补一行 `A 代表数字对且位置对，B 代表数字对但位置不对，目标 4A0B 取胜`。
- **改法**：`guess.historyHint` + `guess.historyHint2`（cn/en 都加），`drawHistory()` 里用 `D.wrapText` 折行，
  `headerH = 行数 × 12 + 4`（原来是写死 18）；记录行按剩余高度等分，不用另算。
- **坑**：375×667 的记录区只有 225px，两行提示后每行只剩 **45px**，而一行的内容是「数字格 28 + 结果行 16」= 45，
  所以行高只能给 12、header 边距只能给 4；再大一点就会出现记录行互相压住（325 以下直接不够用）。
- **规则**：记录区顶部提示增删行时，必须同步 `headerH` 并复核「行数 × 行内容高度」是否还装得下。

### 103. 每个游戏独立的静音按钮（帮助 FAB 左边一格）

- **需求**：25 个小游戏都要有自己的静音开关；全局音效关闭时不展示。声音拦截必须做在 `core/audio`，
  不能每个场景自己 `if (!muted)` 一遍 —— 25 处漏一处就是「静音了还响」。
- **实现**：`core/audio.js` 两级开关：全局 `__games_hub__sfx` + 每场景 `__games_hub__mute__<sceneId>`；
  `App.openScene` 里 `audio.setGame(sceneId)`，`play()` 先判全局再判当前场景静音。
  `core/fab.js` 统一画圆形 FAB / 静音 FAB（`drawMute` 在全局关闭时直接 return，不画也不注册命中区）。
- **位置**：静音 FAB 永远在**帮助 FAB 左边**、同尺寸、同 y；原本就在帮助左边的
  模式 / 机器人 / 穿墙 / 骰子 FAB 整体再左移一格。
- **静音隐藏时不能占位**：全局音效关闭后静音 FAB 不画，若坐标在 `layout()` 里写死，就会留下一个空槽
  （用户报过「按钮不见了但还占着位置，中间空一截」）。坐标必须**绘制时现算**：
  `const muteRect = fabKit.muteSlot(helpRect)`（关闭 → null）、
  `fabKit.slotLeft(helpRect, muteRect ? 2 : 1)`（邻居自动右移一格顶上）。
  冒烟脚本会在「全局关闭」那一轮断言邻居与帮助的间距 ≤16px，防止又退回写死坐标。
- **踩坑 1（同名遮蔽）**：`alchemy` / `sort` 的 `drawFabs` 里有局部 `const fab = (rect, ...) => {}`，
  又与顶部 `const fab = require('../../core/fab')` 撞名 → 运行时 `fab.drawMute is not a function`。
  **共享模块一律用 `fabKit` 导入**。
- **踩坑 2（算早了）**：1A2B 的 `helpFab` 先建 `{y: 0}`、`layout()` 末尾才补 `helpFab.y = fabY`，
  在其之前 `leftSlot(this.helpFab)` 会让静音 FAB 停在 y=0。**先建 rect 再补坐标的场景，补坐标时把新 FAB 一起补**。
- **踩坑 3（横向让位）**：1A2B「退格 / 提交」固定 68% 宽、右侧只留两个 FAB；加第三枚 FAB 后整行会从
  **机器人 FAB 底下穿过去**（实测 375 宽时行右沿 239 vs FAB 组左沿 223，压住 16px）。
  让位必须减到**最左那枚 FAB**（`this.fabRowLeft = min(静音, 机器人, …)`），不是只减到静音左沿：
  `optW = min(kw * 0.68, fabRowLeft - (kx + pad) - 8)`。改完 375 宽时行右沿 191，与 FAB 组留 32px 间隙。
  以后任何右下角固定 FAB 组的游戏，底部整行控件都要按 FAB 组**最左沿**让位（冒烟脚本会断言）。
- **验证**：`node scripts/smoke.js 390 844` / `node scripts/smoke.js 375 667`（假 wx + canvas 渲染 25 个场景，
  断言渲染无异常、静音 FAB 与帮助同行同尺寸且紧邻、不压任何命中区、全局关闭时不出现、点静音后 `play()` 不出声）。

### 105. `rgba()` 只吃 `[r,g,b,a]` 数组，别把十六进制 token 塞进去

- **症状**：关灯游戏新画的循环箭头颜色不对（或干脆不显示），控制台没有报错。
- **根因**：`draw.js` 的 `rgba(arr)` 会拼成 `rgba(NaN,NaN,NaN,undefined)`，canvas 直接忽略这次赋值，
  于是沿用上一次的 strokeStyle。`T.muted` 是 `'#5f6b7a'` 字符串（灯色 token 才是数组）。
- **修法**：字符串 token 直接 `c.strokeStyle = T.muted`；只有灯光的 `T.lamp.*`（数组）才走 `rgba()`。
- **规则**：新增颜色用法前先看 token 类型（`theme.js` 里 `lamp.*` 是数组，其余是十六进制字符串）。

### 106. 游戏区下方的一句玩法提示（七款游戏）

- **需求**：2048 / Threes / 消除大师 / 贪吃蛇 / Emoji 下坠，在游戏区下方各放一句很短的玩法说明。
- **实现**：`core/draw.js` 的 `D.hintLine(c, text, y, color)`（10px、弱色、水平居中）；
  文案 key 统一叫 `<gameId>.playHint`；y 取各自的「游戏区底部 + 16」：
  2048 / Threes / 贪吃蛇 = `boardY + boardSize + 16`，Emoji 下坠 = `boardY + boardH + 16`，
  消除大师 = `trayY + trayH + 16`（它的游戏区是「棋盘 + 暂存槽」，提示要放在槽下面）。
- **踩坑 1（i18n 段序）**：mp-game 的 `i18n.js` 是 **`en` 段在前、`cn` 段在后**（和 web 一样），
  按 `helpMsg:` 出现顺序批量插 key，会把中文塞进 en 段、英文塞进 cn 段 —— 界面上就是「切英文显示中文」。
  **加 key 必须显式分辨段位**，并在冒烟里断言两种语言都不含另一种语言的字形（见 `scripts/smoke.js`）。
- **踩坑 2（不占棋盘的地方）**：消除大师的暂存槽下面只剩约 60px、右下角还有 FAB，
  为了让提示离 FAB 远一点而加大底部预留（90 → 120）会把棋盘压小 30px —— **不值得**。
  提示是居中短句，只要「文字右沿 < FAB 左沿」就不会撞按钮（375 宽：273 < 319），保持底部预留不变。
- **踩坑 3（冒烟顺序）**：断言块一度被追加到脚本末尾、也就是「成功/失败」判定**之后**，
  于是反向测试（故意写错文案）仍然报绿。断言必须放在最终 `if (failures.length)` 之前。
- **踩坑 4（文字宽度）**：英文比中文长得多（炼金术 67 字符 ≈ 368px > 375-32），
  一行会被屏幕切掉。按 10px/汉字、5.5px/拉丁估算，**英文控制在 58 字符内**，并在冒烟里断言。
- **踩坑 5（「不撞 FAB」要按文字框量）**：开始只比了「文字右沿 vs 帮助 FAB 左沿」，
  漏了它左边的静音 FAB；正确做法是把提示当矩形，与**每一颗** FAB 做矩形相交（含 y）。
  判完发现：提示离 FAB 行 12px 以上时横向再宽也不撞；仅消除大师因为贴着槽底，才需要靠 12px 的竖直间隙。
- **踩坑 6（棋盘比预留区高 16px）**：消除大师的 `boardSize = unit × UNITS + 16`（内边距），
  但 `unit` 是按 `availH / UNITS` 算的 → 棋盘实际比 `availH` 高 16px，一直悄悄吃掉了底部预留。
  加提示时暴露成「提示压在 FAB 上」；修法是先 `usableH = availH - 16` 再算 `unit`。
- **踩坑 7（legend 的 i18n 没有 helpMsg）**：legend 只有 `help1..5`，批量「在 helpMsg 后插 key」会失败；
  必须按段（en / cn）在各自的 `help1:` 之后插入。



### 107. 上传报 `invalid file: scripts/smoke.js, 1:0 SyntaxError`

- **症状**：开发者工具「上传」报
  `Error: invalid file: scripts/smoke.js, 1:0 / SyntaxError: Invalid or unexpected token`，
  指向文件第一行的 `#!/usr/bin/env node`。
- **根因**：小游戏上传器会把**项目目录下的所有 `.js` 当源码解析**（不只是运行时用到的那些），
  Node 的 shebang（`#!`）不是合法 JS → 整包上传失败。`packOptions.ignore` 当时是空的。
- **修法**（两层都做）：
  1. `project.config.json` 的 `packOptions.ignore` 加 `{ "type": "folder", "value": "scripts" }`
     —— 开发脚本不进包（`build-icons.py` 也一起被排除）；
  2. 冒烟脚本**不写 shebang**，统一用 `node scripts/smoke.js 375 667` 调用。
- **规则**：`mp-game/` 里新增任何「只在开发机上跑」的文件（Node 脚本、tsv/json 数据源、截图工具），
  都要放进 `scripts/` 并确认它仍在 `packOptions.ignore` 覆盖范围内；不要给项目内的 `.js` 加 shebang。

### 108. 静音「一处静音、处处静音」（各游戏没独立）

- **症状**：在任意一个游戏里点静音，之后进别的游戏也全是静音；静音 FAB 的图标在所有游戏里同步变化。
- **根因**：`core/audio` 的「当前游戏」只在 `App.openScene` 里同步，而**进游戏走的是 `App.openGame`**
  （它直接 `this.sceneId = id`），于是 `audio` 的 gameId 一直停在 `'home'` —— 所有游戏都读写同一个
  `__games_hub__mute__home`。
- **修法**：`App` 里新增唯一入口 `setSceneId(id)`，`openScene` / `openGame` / `goHome` 全部改走它，
  里面同步 `audio.setGame(this.sceneId)`；`audio.js` 启动时顺手删掉旧版残留的
  `__games_hub__mute__home`。
- **验收**：`scripts/smoke.js` 里有一段真实 `App` 的回归用例：
  进关灯 → 点静音（写 `__games_hub__mute__click`）→ 进对对碰（必须**未静音**、`playSuccess()` 有声）
  → 回首页（不沿用）→ 再进关灯（静音还在）。把 `openGame` 改回只赋 `sceneId`，这段会立刻报 4 处失败。
- **规则**：凡是「与当前场景绑定」的模块状态（音效静音、分享标题、埋点场景名…），
  都必须在 `App` 的**同一个入口**里同步，不能只挂在 `openScene` 上 —— 进游戏不一定走 `openScene`。

### 109. 小游戏里没有 `clip-path`：圆形展开要用「离屏画布 + arc/clip/drawImage」

- **需求**：设置面板要像 web 的 `clip-path: circle()` 一样，从齿轮位置以圆形展开 / 收拢。
- **做法**：
  1. 面板内容抽成一个纯绘制函数 `drawSettingsContent(ctx, { L, scroll, interactive })`（不含动画壳）；
  2. 动画期间把它画到**离屏画布**（`wx.createCanvas()` —— 第一次调用返回主画布，之后才是离屏），
     再在主画布 `save → beginPath → arc(圆心, 半径) → clip → drawImage(离屏, 0, 0, W, H) → restore`；
  3. 完全展开（ease ≥ 0.995）直接画主画布，省一次全屏 drawImage；
  4. 圆心 = 齿轮中心，半径从 0 到「到最远屏幕角」的距离（不是固定值，否则小屏会露角）；
  5. 内容比圆形晚显形：`globalAlpha = clamp((ease - 0.18) / 0.5)`（web 是 opacity .28s delay .16s）。
- **坑 1（DPR 内存）**：离屏画布按 `W×H×DPR²×4B` 占内存，DPR 3 时一块就十几 MB；这块只用于 0.6s 动画，
  `dpr = min(DPR, 2)` 足够。
- **坑 2（拿不到第二块画布）**：有的基础库 `wx.createCanvas()` 可能返回主画布或失败 —— 必须判断并
  **退化成直接显示**（不播动画，但绝不崩）。
- **坑 3（动画期间别注册按钮）**：圆形还没展开完时面板只露出局部，按钮要 `ease` 够了才注册，
  否则会点到看不见的选项（与 web 一致：动画期间不可交互）。
- **坑 4（底色必须在圆形里铺，不能只靠离屏）**：用户报过「展开过程中首页蜂窝能透出来、展开完才盖住」。
  根因是把**整个面板（含底色）**都画进离屏画布，再整体套 `globalAlpha` 淡入 —— 底色跟着一起变透明。
  正确顺序：`clip` 之后**先 `fillRect` 铺不透明底色**，再按 `globalAlpha` 画「只有内容」的离屏位图；
  离屏画布每帧 `clearRect` 保持透明底（`drawSettingsContent` 里不要再画底色）。
- **坑 5b（卡片区域要「吞点击」）**：遮罩是整屏的，点卡片标题 / 卡内空白也会关闭面板。
  做法：在选项按钮之前，为每张卡片矩形和标题徽章各注册一个**空热区**（`addBtn('settings-panel-<i>', …, () => {})`），
  于是「点卡片 = 无反应、点卡片外的空白 = 关闭、点 ✕ = 关闭」。热区 `y` 同样要减 `scroll`。
- **坑 5（遮罩必须最先注册，否则选项全点不到）**：用户报过「设置里的项目完全改不了，点任何地方都关闭」。
  根因是整屏遮罩 `settings-mask` 在内容**之后**注册 —— 命中判定是「后注册优先」，于是每一次点击都落到
  遮罩上（= 关闭面板），选项按钮永远命中不到。修法：`addButton('settings-mask', …)` 放在画内容之前，
  选项 / 开关 / 关闭按钮在之后注册；同理，别的「整屏遮罩 + 内容按钮」浮层（帮助、二次确认）也用这个顺序。
- **验证**：冒烟脚本记录 ctx 的 `arc/clip/drawImage` 调用，断言动画中间帧确实走了裁剪、
  且此时没有 `setting-*` 按钮；另外按坐标模拟点击（`点 setting-0-light` 必须命中自己、改主题且不关面板），
  并断言按钮数组里第一个 `setting-*` 的下标必须大于 `settings-mask`。把遮罩改回最后注册会立刻报 5 处失败。



### 110. Android 上 emoji 在卡片里偏左 / 偏下甚至溢出边框

- **症状**：同一个小游戏，iOS 牌面正常；部分 Android 机型上 emoji 明显往**左下**偏，个别字形顶出卡片边框。
- **根因**：
  1. `measureText()` 的 `actualBoundingBox*` 在微信自绘 canvas（Android）上经常**不返回**，代码退回
     `textBaseline='middle'`；而 `middle` 的基准来自字体 ascent/descent（含 emoji 字体的行高垫），
     Noto Color Emoji 上会整体偏下；
  2. 退回分支还继承了为 iOS 调的 `+0.18em` 光学下移（约 5px @28px 字号），把偏下进一步放大，于是溢出边框；
  3. 横向只靠 `textAlign='center'`（按 advance 居中，不是按墨迹），字形左右留白不一致的字形看起来偏左。
- **修法**（`js/core/cards.js` 的 `drawEmoji` + `js/core/emoji-box.js`、`js/core/platform.js`）：
  **分流信号用「有没有 `actualBoundingBox`」，不要用平台名。**
  - 有 metrics（iOS、开发者工具、连 Android Profile 的 Nexus 也有，因为宿主是 Apple Emoji）→ 老逻辑
    （墨迹中心 + `0.18em`），与历史版本逐像素一致；
  - 没有 metrics（微信自绘 canvas 的真机 Android，如 vivo）→ 纵向 `textBaseline='middle'`（**去掉** 0.18em），
    横向用离屏画布量墨迹偏移修正。
  - ⚠️ 踩过两次：①「非 iOS 用新逻辑」→ iOS `platform` 取不到，误判 → 全局上移 5px；
    ②「确认 Android 用新逻辑」→ 开发者工具的 Nexus Profile 平台名是 android、但渲染用 Apple Emoji →
    又上移 5px。**平台名不可靠，metrics 的可用性才可靠。**
  - 另：Android 真机原来的「偏下」正是 `0.18em` 加多了（它是为 Apple Emoji 的墨迹/em 中线差补的），
    所以无 metrics 分支用 em 中线、不再加光学偏移。
  - 非 iOS：有 `actualBoundingBox` 就按 `(right-left)/2`、`(ascent-descent)/2` 把**墨迹中心**放到卡片中心；
    没有就用离屏画布逐字画一遍 + `getImageData` 找墨迹包围盒（按 `字号|字形` 缓存，每个字形只量一次，96×96 canvas 仅 36KB）；
    两者都没有就退回 `middle` 基线，**不加**光学偏移。
  - 离屏画布的第一次 `wx.createCanvas()` 会拿到主画布，必须与 `core/canvas.js` 的 `canvas` 比较后拒绝，否则会画花主屏。
- **验证**：冒烟脚本用 `EMOJI_INK=1` 让假 `getImageData` 在中心偏 (3, 6) 画一块墨迹，断言
  `emojiBox.measure()` 的 `dx=3`、`dy=6-size*0.45`，并断言 `drawEmoji` 的落点 = `中心 - 偏移`；默认（无墨迹）返回 null 且不抛错。

### 111. 暗黑模式下的胜利 / 失败遮罩是一块白板

- **症状**：浅色模式正常；切到暗黑后，three / link / 2048 / Emoji 下坠 / 贪吃蛇 / Emoji 镜像 的胜负遮罩
  是一整块近白色，`T.win`（暗色主题下是亮绿）和 `T.lose`（浅红）几乎看不清。猎手 / 侦探 / 消除大师正常。
- **根因**：这几个游戏的结算遮罩写死了浅色（`rgba(250,248,239,0.88~0.9)`），没有走主题 token；
  暂停遮罩（下坠 / 贪吃蛇）是同一个问题。文字颜色其实是对的（`T.win` / `T.lose` 本身随主题变），
  真正错的是**遮罩底色** —— 亮色文字压在亮底上。
- **修法**：结算 / 暂停遮罩统一用 `T.overlay`（亮白 0.8 / 暗 #333 0.8），与猎手一致；
  需要更不透明的游戏保留 `theme.dark ? 'rgba(38,38,38,0.94)' : 'rgba(250,248,239,0.94)'` 这种**显式分支**。
- **防回归**：`scripts/smoke.js` 静态扫描所有 `js/games/*/scene.js`：只要某行出现
  `rgba(250,248,239` 或 `rgba(38,38,38` 却没带 `theme.dark` / `T.overlay`，直接报错
  （反向测试：随便改回一处写死的浅色会立刻失败）。

### 112. 1A2B 的胜负遮罩盖住了键盘

### 113. 扑克：牌组区提示的竖向预算 / 猜大小飞牌

- **需求**：牌组区上方加一句阶段提示；猜大小卡加一行「7 平局，>=8 为大，<=6 为小」；
  点「大 / 小」后让右侧那张牌飞到左侧历史位。
- **提示出现时机 / 行数 / 行距**：发牌前一行（点发牌）；**发牌后换牌前两行**（先讲“点牌保留再换牌”，第二行讲大小王），
  两行基线 `cardsY + 9 / + 22`（行距 13），区块 28px；猜大小头部两行行距 12.5（`guessY + 8.5 / + 21`）。
  换牌后不显示。高度按**两行**常驻 24px（`tableHintLines()` 返回数组，换牌后返回空数组但高度照留），
  这样牌桌不会因为提示行数变化而上下跳。两行把牌桌挤小的问题用“收紧上方固定间距”补回来：
  牌型倍数 caption 16→14、两处 14→12，共 8px；375×667 上牌 50×75 保持不变。
- **竖向预算**：牌桌高度由 `natural = cardH + holdH + 12` 与 `maxCards` 共同决定。
  加 16px 提示必须把它写进 `natural`，否则牌会顶到提示上。375×667：`maxCards = 127`，
  所以牌从 87 缩到 81 才正好放下（提示 16 + 牌 81 + 保留 18 + 余量）。
  `maxCards < 120`（320×568 只有 50）时**不要硬塞**，直接把 `tableHintH` 归 0。
- **猜大小卡头部 / 高度**：单行 `guessTip` 时 `contentTop = guessY + 18`；两行后头部要吃掉 28px，
  而此时 `guessH`（web 200rpx = 100）已经不够：`头部 + 2 + 牌 57 + 标签 12` 需要 99，只剩 98 → **标签底边被裁**。
  两个修法一起用：① 猜大小区 `guessH += 6`（375 下 106）；② 头部高度按 `clamp(guessH - miniH - 18, 20, 28)` 算，
  18 = 2 顶距 + 12 标签 + 4 底距。紧凑卡（320×568）再把历史牌缩到 28×42、当前牌 36×54。
  ⚠️ 加高猜大小卡会挤掉牌桌：375×667 的 `maxCards` 从 127 掉到 121，牌从 54×81 缩到 50×75；
  紧凑阈值也要跟着从 `maxCards < 120` 调到 `< 110`，否则 375 会被误判成矮屏、反而变矮。
- **飞牌**：历史条目仍要在 `guess()` 里**立即**入 `guesses`（存档要一致），只是绘制时跳过「正在飞」的那条
  （`fly.index`），由飞行中的那张牌顶替；落地（`now - at >= 320`）后在 `update()` 里清状态并换新牌。
  没有这个 `!this.guessFly` 保护，闪烁逻辑会立刻把新牌塞回右侧，出现「两张牌」。
- **验证**：`POKER_PROBE=1 node scripts/smoke.js 375 667` 打印牌桌/猜大小几何；
  冒烟还会跑一段：`guess(true)` 后 `guessFly` 存在、右侧无新牌、历史 +1、飞行 0/120/240/320ms 渲染不抛错，
  再把 `at` 往前挪 400ms 调 `update()` 断言状态清掉且右侧出现新牌。

### 115. 帮助弹窗改「毛玻璃 + 圆形展开」

- **毛玻璃**：canvas 没有 backdrop-filter。做法是每帧把主画布 `drawImage` 到小画布（1/5）再放大画回来，
  最后盖一层淡色；开销只有一次 75×134 的 drawImage。拿不到第二块画布时退回纯半透明遮罩，绝不崩。
- **「看着像马赛克」的修法**（改了两版才对）：
  - 第一版：1/8 下采样 + `drawImage` 放大 → 基础库 `imageSmoothingEnabled` 默认 false 时是**最近邻**，8px 硬方块；
  - 第二版：补了 `imageSmoothingEnabled/Quality` + `ctx.filter='blur()'` 探测 + 两级放大 —— 真机上仍然偏「块」，
    因为这两项能力在各家基础库上不可靠（filter 大多没有，smoothing 有的机型不生效）；
  - 第三版（现在）：**不再依赖 canvas 的平滑能力**，把模糊放到像素层做 ——
    1/2 采样 → `getImageData` → `core/blur.js` 的可分离盒式模糊（`BLUR_R = 5`，2 遍 ≈ 高斯）→ `putImageData`
    → 放大 2 倍（就算最近邻也只有 2px 台阶）。`core/blur.js` 是纯函数，Node 里能直接断言：
    均匀画面不变、单点向邻格扩散、远处不受影响、alpha 保留。
  - 只在打开帮助的第一帧算一次（`s.backdrop` 缓存）—— 场景在帮助打开时本来就冻结；
    冒烟用 `putImageData` 的调用次数断言「一次展开只算一次」。
  - **抓图有效性**：读回来的像素如果整屏一个颜色（`hasDetail()` 抽样比较 R 通道极差 ≤ 2），
    说明抓图失败或画面本来就平，直接退回纯半透明遮罩；失败结果也缓存成 `s.backdrop = false`，
    否则会「每帧重抓一次」，白白烧 CPU。
- **圆形展开**：和首页设置面板同一套 —— 圆心用帮助 FAB 中心，半径 0 → 最远角，
  **展开 600ms / 收起 480ms**（别用早先的 260ms，比首页快一倍，看着像「啪」地弹出来），
  内容 `clip` 在圆里；按钮只在完全展开后注册，动画期间点不到。
  `App.render` 要改成「`helpOpen` 或 `help.animating()` 都画帮助」，否则点关闭后动画立刻消失（没有收缩过程）。
- **关闭 ✕**：展开后把帮助 FAB 那一格画成圆形 ✕（`T.card` 底 + 阴影 + `icons` 的 close，失败退回 `×` 文字），
  透明度 `(ease-0.45)/0.4` 淡入、`ease > 0.75` 可点；和首页设置面板把齿轮变 ✕ 一致。
  注意注册顺序：`help-close` 先注册、全屏遮罩 `help-mask` 后注册，遮罩命中优先级更高（点到 ✕ 也等于关闭遮罩，结果一致）。
- **「动画根本没出现」的两个真凶**（第一版实现就踩了）：
  1. 第一帧 `dt` 用了 `ANIM_MS`（本意是没有上一帧时按一整段算）→ `anim` 一步到 1，直接完全展开；
     必须让第一帧 `dt = 0`（只记 `s.at`），下一帧才开始推进；
  2. 毛玻璃底画在 **clip 之外** → 一打开整屏立刻模糊，只有面板在动，看不出圆形。
     正确顺序：`arc + clip` → 圆内铺毛玻璃 → 圆内画面板（圆外保持原画面）。
- **抖动坑**：动画推进写成 `anim = target > anim ? min(1, anim + dt) : max(0, anim - dt)`
  在 `anim === target === 1` 时会走减法分支 → 每帧在 1 / 0.92 之间跳，按钮交替注册/丢失，
  表现为「关闭按钮时有时无」。必须写成 `if (anim < target) … else if (anim > target) …`。
- **冒烟**：动画用 `Date.now()`，一次性循环调用不会推进时间 —— 测试里临时把 `Date.now` 换成可控时钟
  （每帧 +20ms）跑 20 帧再断言关闭按钮；同时记录每帧**第一个** `arc` 的半径，断言展开时逐帧变大、
  收到最远角，收起时变小（注意：项目符号的小圆点也是 `arc`，所以只取第一个）。
- **圆心**：`fabCenter()` 依次取 `scene.helpFab` / `helpRect` / `fabX+fabY+fabSize`，都没有才退回右下角常量；
  各游戏字段名不统一，别只认一种。

### 118. 成就系统：指标口径与「名称退化成 id」

- **为什么成就优先读已有存档**：25 个游戏里 21 个有胜场、绝大多数本来就把 `best/level/streak` 存好了；
  再单独记一套「进度」只会和游戏内显示打架。只有「累计对局 / 累计胜利」游戏本身没有，才自己记
  （`__games_hub__achv` 的 `plays` / `wins`）。
- **口径坑（都实测过）**：
  1. `best_1` 的 1 是**存档位/模式号**，不是第一名；同一指标可能有 `_2` / `_3`（不同牌面），取 `maxOf`。
  2. `best` 语义分三类：已通关+1（link / crush / detective / hunter / gambler）、已开始的最高关
     （match / sort / alchemy / mahjong / quesheng）、最高分或最短用时（2048 / three / snake / down / legend /
     sudoku / mirror / click / puzzle）。文案写「通关第 N 关」还是「最高分 N」要跟着语义走。
  3. 时间类（sudoku / mirror）和步数类（puzzle）是**越小越好**，要用 `{ lte: true }`，否则永远显示未达成。
  4. click 的 best 只在「破纪录且 score>0」时写 → 「第一次通关」只能数 `wins`。
  5. `__emoji_slide__` 没有 best / level 键，关卡只在 `state` JSON 里 → 用 `readJsonField(state,'level')`。
  6. snake / three / down / legend **没有胜利态**，硬塞 `achv.win()` 会永远不触发。
- **名称退化成 id**：`achv.js` 需要 `home.<id>Title`，但 home 的 i18n 是**导出 dict、由 home 场景注册**的；
  `achv` 单独被 require 时命名空间还没注册，卡片标题就会显示成 `click`。现在 `achv.js` 里显式
  `i18n.register('home', require('../games/home/i18n'))`，冒烟也加了「名字不能等于 id」的断言。
- **小红点**：`win()` 里比较解锁数前后差异，只有真的多解锁才 `seen = false`；打开成就页 `markSeen()` 清掉。
- **页面性能**：25 张卡每帧直接画（不是离屏合成），文本量不大；烟花粒子上限 16 + 3 朵×14，够用且便宜。
- **成就档位差一关**（写完自查时抓到的真 bug）：link / crush / detective / hunter / gambler 的 `best` 是
  **已通关 + 1**，直接 `value >= N` 会让「通关第 5 关」在第 4 关就解锁。统一用 `cleared(best) = max(0, best-1)`
  再比较。做成就前先把每个 key 的语义抄在 SPEC 旁边，别凭名字猜。
- **成绩行不要露出 0**：`最佳 0 关` / `— 连胜` 都像 bug。用 `V()`（0→`—`）、`lvOf()`（0→`—`）、
  `withUnit()`（0 → 整个单位一起省略）三个小工具处理。
- **别三条都同一指标**：早先 Threes / 传奇 / 下坠 都是「分数三档」，读起来像占位。改成
  「首次 → 里程碑 → 极限」的混搭，或干脆 2 条。
- **指标行（`stat: true`）的 ratio 必须显式归零**：`ratio` 默认按 `value/target` 算，
  指标行的 `target` 是 1，value 一有值就会画成「满格进度」，看起来像已完成的成就。`gamesData` 里
  `if (r.stat) { r.ratio = 0; return; }`，冒烟也断言了 `stat` 行的 ratio 必须是 0。
- **峰值 / 计数要分清**：`peak()` 只在比历史大时才写（最高资产、单次最高奖金、最大单次得分、最长连胜），
  `bump()` 是无条件累加（四条 / 同花顺 / 字牌消除 / 5 次摸牌内获胜）。用错会被「最大值」覆盖掉次数。
- **单人麻将没有关卡**：`__solo__*` 只有 state / streak / best_streak，所以「最高关卡」这条口径不存在，
  别硬造一个假关卡；同类情况（某游戏没有该维度）宁可少一条也别编数据。
- **雀圣两个模式**：mode 1 = 滑底（老模式，30 步）、mode 2 = 步进（一次一格，50 步）；成就里分别叫
  滑底 / 步进，别对调。
- **`achv.win()` 千万别放在每帧都跑的 update 里**（真 bug）：数独早期写成
  `update() { … achv.win('sudoku'); }`，结果每秒 +60 次胜场，「累计 100 胜」几分钟就满。
  正确位置是「状态从 PLAY 变成 WON 的那一次转折」里，并且要有 `phase` 守卫。
  同理 `trackPlay` 只在 `openGame` 调、`reach` 只在一局结束调。
- **`reach()` 的数值要取「本局最终值」**：蛇 / 下坠 / 2048 / Threes 都在判负（或无法移动）那一帧读
  `this.score`；不要在吃一口 / 合并一次时调，否则一局能涨几十次。
- **滑行的「无重排」**：`checkDeadlock()` 里只要调过 `reshuffleBoard` 就置 `usedShuffle = true`，
  `startLevel()` 里清掉；成就用 `perfect: !usedShuffle` 上报。
- **难度类成就的兼容**：数字迷宫 / 镜像 / 数独的历史记录就在各自难度的 key 里
  （`__number_puzzle__<n>` / `__emoji_mirror__best_<d>` / `__sudoku_game__<d>`），
  `diffDoneCount()` 同时看「成就自己记的 modes」和这些 key，老玩家不会被清零。
- **隐藏成就的三个埋点都容易写脏**：
  1. **时长别每帧写存储**：`addPlayMs` 只在内存里累加，满 3 秒或 `wx.onHide` / 切场景才 `flushTime()`；
     每帧 `setStorageSync` 会明显拖慢帧率。
  2. **失败次数别在场景里数**：25 个场景各自 `playLose`，统一由 `audio.setLoseHook` 注入回调
     （`core/audio` 不直接 require 成就模块，避免依赖环）。
  3. **帮助看过要按场景去重**：App 里用 `markedHelp` 记住当前场景，`scene.helpOpen` 首次为真才记一次，
     否则每帧 +1，集齐 25 个会瞬间达成。
- **「超过了第 N 关」的阈值要用「已通关数」，不是存档里的「当前关 / 最高关」**
  （踩过：我爱闯关要求 `>= 11`，但 8 个闯关游戏的存档是 `best = 已通关 + 1`，
  玩家通过第 10 关时存档是 11、已通关数是 10 —— 写成 11 就永远差一关，只有 master 能过，一直显示 1/9）。
  统一用 `bestClearedOf(id) >= HIDDEN_PASS_LEVEL`（`HIDDEN_PASS_LEVEL = 10`），
  冒烟对「通过第 10 关解锁 / 只到第 10 关不解锁」两个方向都做了断言。
- **列表末尾新加卡片，`contentHeight()` 一定要同步**（踩过：隐藏成就卡加在 `cardList` 里，
  高度没算进 `contentHeight`，滑到底只露出半张、被底部渐隐压住）。判断标准：`cardList(maxScroll())`
  最后一张的 `y + h` 必须 ≤ `viewH()`，冒烟已经断言这一条。
- **「牌型达成」这类统计要在达成那一刻记，别挂在结算上**（踩过：四条 / 同花顺写在 `settle()` 里，
  玩家中牌型后猜大小输了就白得一手号 —— 结算根本没跑到）。改到 `resolveHand()` 评牌时记，
  并用 `silent` 参数挡掉恢复存档的重复计数。

  450ms 的翻转动画里、部分正面可见，等于把「哪张被换了」直接演给玩家。正确做法是等
  `flips.every(f => f <= 0)`（每张牌各自有 `i*20ms` 错峰 + 450ms 行程）之后再换，再留 160ms 全背面才揭面。
  冒烟里用 16ms 假时钟逐帧跑，断言「换牌那一帧没有一张牌是朝上的」。
- **只在结算时存盘 = 中途退出丢进度**（侦探）：`saveState()` 原来只在 WON/LOST 调，`onHide()` 是空的，
  于是关掉小游戏再回来 `restore()` 读到空 → `startLevel()` 从第 1 关重开。而且答题态以前根本不存，
  玩家退了再进等于白答。现在观察阶段 / 换牌完成 / 进入答题 / 每次作答 / 胜负 / `onHide` / 切模式都写；
  `restore()` 区分「接着答（含已用时间、心数、点错的格子）」与「观察阶段直接重开本关」。
  测试时注意 `withFakeClock` 的作用域：`playStart` 一旦在旧时钟里设定，换新时钟再算 elapsed 会变成负数。
- **成就实时提示曾经整条漏掉过（2026-11 修）**，三个原因叠在一起：
  ① `peak()` 为了省开销把快照节流到 400ms —— **恰好落在被节流那一次上的解锁就永远不会弹**
     （之后每次快照都已包含它，再也不会「新」）；② 隐藏成就的写入口（`markHelp` / `markFail` / `flushTime`）
     根本没做检查；③ 快照用「游戏名·成就名」当身份，**名字会随语言变**，切一次语言等于把全部成就
     当成新解锁（反过来也会因为重名漏判）。
  现在的写法：快照身份用稳定 key（`<游戏 id>#<行号>` / `hidden#<key>`），维护一份
  `knownUnlocks` 基线，每个写入口改完存盘调一次 `fireUnlocks()`；`peak()` 这种每消一组就调的热路径
  **只打 `unlockDirty` 标记**，由 `App.frame` 每秒一次的 `achv.sweepUnlocks()` 补查（顺带也能兜住
  「场景自己写存档、没走 achv」的解锁）。第一次只建立基线，不会把老存档的成就一次性弹出来。
  另外快照里加了「一次快照内同一 key 只读一次」的读缓存 —— `wx.getStorageSync` 是 JSBridge 同步调用，
  一次快照原本要读一两百次，真机上十几毫秒；缓存后 `sweepUnlocks()` 约 0.2ms（冒烟实测）。
- **成就解说的话要「改前改后各取一次快照」**：`achv` 的 mutator（win / reach / bump / peak / trackPlay）里
  先 `unlockedSnapshot()`，改完再取一次 diff，才能知道**具体哪一条**新解锁（只看 `unlockedCount` 增减拿不到名字）。
  成本约 0.1~0.2ms；`peak` 在消除类游戏里一局要调很多次，所以那一条做了 400ms 节流。
  提示条与每日挑战共用 `App.pushToast` 队列，别各写一个 —— 两个同时触发会叠在一起。
- **`recent` 只记还在池子里的任务 id**（踩过：把已下线的 id 也 push 进「最近 5 天」，它会占掉一个名额，
  于是真正该排除的那条被挤出去，5 天不重复的保证就漏了）。
- **`A()` 只是定义，不是可渲染的行**（踩过：`dailyCard()` 直接把 `A(...)` 塞进 `achv`，
  页面渲染全是 undefined、冒烟里 `rows[3].value` 也是 undefined）。自定义卡片要自己走一遍
  `progressOf(def)` 并算出 `ratio`，或者复用 `gamesData()` 那套解析。
- **整屏面板必须先铺不透明底**（踩过：每日挑战页只画了顶部渐变，首页蜂窝从底下透上来，字几乎看不清）。
  一律 `c.fillStyle = T.bg; c.fillRect(0, 0, W, H);` 再叠淡色渐变 —— 成就页就是这么做的，别学漏。
- **每日挑战的任务要在「当下」就能完成**：`achv.reach` 是**一局结束**才上报的，
  2048 / 贪吃蛇 / 下坠 这类要在分数或牌面变化的当帧补 `daily.report(game, 'reach', { value })`，
  否则玩家打到目标却没提示，要等判负才弹。
- **任务池会变，老存档里的任务 id 可能已经不存在**（踩过：下线「滑行 / 扑克四条 / 连连看第 6 关」之后，
  模拟器里当天那条挑战还在存档里 → 面板任务文案空白、红点永远消不掉、也永远完成不了）。
  现在 `healToday()` 兜底：今天这条不在池子里、又没完成 → 当场换一条；已完成 → 保留完成状态 +
  `retired` 标记（**这个标记必须存进存档**，否则每次读都判定「要修复」并写一次存档）。
  以后改 `POOL` 的 id 或删任务，都靠它自愈，不用手动清存档。
- **累计次数不能只从 `days` 数**：`days` 只保留最近 400 天，数久了会变少；单独存 `total`，
  老存档（没有 `total`）在 `finish()` 里用「已有完成天数」垫底再 +1，避免从 1 重新数。
- **「分数类」每日挑战必须绑到「今天新开的一局」**（踩过：用 `achv.reach` 那种只上报当前分数的方式，
  老存档里已经有 1024 块的玩家一进 2048 就直接完成「最高牌到 512」）。做法是场景 `startGame()` /
  `startNewRun()` 里 `daily.markNewRun(id)`，`report('reach')` 看 `cur.runs[id]` 才计数；
  恢复存档的路径绝对不要调，否则秒完成。
- **每日挑战别写「回到第 N 关」**（踩过：连连看第 6 关 / 消消乐第 10 关 / 消除大师第 6 关 / 麻将英雄第 5 关）：
  这些游戏的关卡只能往前推，过了就回不去；`achv.win` 上报的 `level` 虽然是「本局通关的关卡」，
  但写成任务文案就变成玩家「必须重开一局从第 1 关爬」。涉及关卡的游戏一律用「赢一局 / 赢 N 局」。
- **难度别靠运气**：任务写成「猜大小连中 5 次」这种，通过率极低；一局内可稳定达成的量级才合适。
- **每日挑战别在 25 个场景里各写判定**：统一挂在 `achv` 的 `trackPlay / win / reach / peak / bump` 上，
  再加一条 `daily.report()`；不然后面新增任务又得改 25 个文件。
- **跨天要重新抽题**：`report()` 发现 `cur.date !== 今天` 时会先 roll 再判定，
  否则「昨天没做完的任务」会在今天被同一件小事算完成。
- **`achv.win` 的插入位置要看清**：第一次把 `daily.report(..., { value: v })` 插进了 `win()`（那里没有 `v`），
  一跑就 ReferenceError。埋点插完要 `node --check` + 跑一次真实事件，别只看语法。
- **边缘手势归 App 管，别在场景里各写一套**：`startEdgeSwipe` / `moveEdgeSwipe` 统一判断
  （左右 20px、内滑 72px、竖直 ≤40px），首页只有在 `overlayOpen()` 为真时才拦，否则完全不碰；
  场景提供 `overlayOpen()` / `closeOverlay()` 即可（设置 / 成就面板都走这一套）。
- **安卓全面屏手势的「边缘返回」拦不住**（踩过：vivo 上从屏幕边缘内滑直接退出小游戏，还以为是自己的手势代码）。
  那次滑动由系统 / 微信在触摸到达 canvas 之前消费，小游戏没有禁用返回手势的 API；
  只能靠面板内提供足够的关闭入口（✕ / 点遮罩 / 边缘内滑）。
- **烟花的「密集」靠调间隔，不靠叠同屏数量**：每 0.7~1.5s 一朵、同屏最多 4 朵、每朵 12~17 颗粒；
  再密就会从「氛围」变成「干扰」（毕竟它现在画在卡片**之上**）。想更热闹先加颗粒/碎金，别再缩间隔。
- **左列只有 ~103px 宽，英文游戏名很容易溢出**（踩过：`Hidden achievements` 直接冲出卡片）。
  名字统一走 `wrapName()` 按空格折行、最多两行，整组按块高重新居中；
  新增英文名时别再自己算 y 坐标，交给这一套。
- **成就页的卡片配色只有一处**：`glassCard()` 内部走 `cardColors(dark, allDone)`，
  「全部达成 → 浅橙」只改这一处，别在 `drawCard` 里再叠一层别的底色（会盖住半透明和烟花）。
- **冒烟里伪造进度后要 `achvPage.setData(achv.pageData())`**：页面数据是打开成就页时快照的，
  不刷新就还是旧进度（踩过：断言「全达成卡片是橙的」怎么都过不了）。
- **绿字压绿底等于看不见**（踩过：暗色主题里「已达成 / x 次」用 `T.primary` 描在主色绿的填充上，
  对比度不到 1.2）：成功态的**文字与图标**在暗色主题一律改白色，只在亮色主题继续用主色绿。
  以后凡是「成功色文字 + 成功色底」的组合，先想暗色主题下的对比。
- **进度药丸：底色保持中性、只给「已完成比例」上色**（需求原话）。底轨 `rgba(255,255,255,0.05)` /
  `rgba(0,0,0,0.035)`，填充是浅绿（暗 `rgba(79,158,116,0.88)` / 亮 `rgba(143,211,175,0.92)`）。
  ⚠️ 浅绿上还要压成就名文字：太浅（比如白绿 `#d9efe2`）在暗色主题里浅色文字会糊掉 ——
  这两个值是按两种主题的文字色都试过挑的。
- **拖动的卡要在最后画**：遍历时跳过 `drag.index`，循环结束后单独按手指位置画（带抬起阴影），
  否则它会和原槽位那张重叠两次、看起来像闪了一下。
- **「滚动不平滑」的三个真凶**（都实测）：
  1. **卡片阴影**：每张卡 `shadowBlur = 12` 的半透明圆角矩形，一屏 4~5 张、每帧重画，
     在微信 Android 自绘 canvas 上非常贵 → 滚动/拖动期间传 `flat=true` 关阴影，停止后自动恢复；
  2. **每帧新建渐变**：顶部主色渐变、底部渐隐原来都 `createLinearGradient`，改成按主题缓存；
  3. **没有惯性**：松手立刻停，手指一停画面就「卡住」，观感也差；现在按采样算速度、×0.94/帧 衰减。
  另外触摸开始要先清惯性，否则「按住」时内容还在自己滑。

### 117. 背景「点 + 连线」太单调，换成多层浅景

- **旧实现**：`core/particles.js` 20~54 个点，两两距离 < 120 就画一条线。问题：视觉上就是一片网格，
  安静但没有生气；点多的时候连线又显得脏。
- **新实现**：四层 —— 光斑（4 团径向渐变，色相 50s 一轮在绿/蓝/紫间插值）、蜂窝（10~16 个空心六边形，
  呼应首页，缓慢上浮 + 自转）、微尘（约 1/4 是四芒小星）、流星（9~16s 一颗，2.2s 斜穿，带渐隐尾巴）。
  全部低透明度、慢速；内容卡片是不透明的，所以只在留白处透出来。
- **别踩的坑**：
  1. 光斑外圈描边（`stroke` 一圈圆）在深色主题下会像「脏环」，去掉，只留渐变；
  2. 流星必须淡入淡出（前 15% / 后 35%），否则会「凭空出现、突然消失」；
  3. 流星要清掉（`t >= dur` 置 null），冒烟里断言「出现后会被清掉」，避免每帧都画一条静止的尾巴；
  4. 背景每帧**只准** fill / stroke / 渐变，禁止文字和 `drawImage`（冒烟有断言）；
  5. 元素要回收：越界 80px 外必须 wrap，否则跑久了会全挤到一边。
- **「太淡了看不见」**：第一版光斑峰值只有 0.09/0.105、蜂窝 0.085/0.10，实际在手机上几乎看不出来。
  现在整体抬高到 —— 光斑 暗 0.21 / 亮 0.16（第 4 团一半）、蜂窝 暗 0.20 / 亮 0.17、
  微尘 暗 0.40 / 亮 0.34、流星尾 暗 0.28 / 亮 0.22、流星头 0.62 / 0.50。
  **判断标准**：把内容卡片全部盖住只看留白，应该能一眼看出「有光、有蜂窝、有星点」，但仍读不出具体形状。
  ⚠️ **暗色 / 浅色必须分开调**：第一轮按同一个比例抬，暗色够了、浅色还是「什么都没有」。
  浅色最终用 光斑 0.30 / 蜂窝 0.32 / 微尘 0.52，并把浅色调色板换成更深的
  `18,92,58` / `30,74,140` / `86,52,140`、微尘用 `52,70,96`。**改一个主题就顺手看一眼另一个主题。**
- **性能**：4 个渐变 + 12~20 个路径 + 二十来个点，固定预算，不随分辨率增长；不做离屏合成。

### 116. 界面上显示成了 i18n 的 key

- **现象**：扑克英雄牌组区上方那句提示显示成 `poker.tableHintDeal`。
- **原因**：改帮助文案时为了恢复被写坏的 i18n 文件，执行过
  `git checkout HEAD -- js/games/*/i18n.js` —— 这些 key 当时还是**未提交**状态，直接被回滚掉了；
  代码里 `t('poker.tableHintDeal')` 找不到 key 时返回 key 本身，于是原样画到界面上。
- **教训**：`git checkout -- <file>` 会连未提交的改动一起吞掉，只该用在「这个文件的改动全是坏的时候」，
  且要先把里面的新增内容抄出来（这次 `guessRule` 记得补了，三个 `tableHint*` 忘了）。
- **防复发**：冒烟新增「场景里用到的 key 必须存在」检查 —— 用正则抓 `scene.js` 里所有
  `t('<gameId>.<key>')` 字面量，中英两种语言各查一次，缺一个就失败并指名是哪个语言。
  动态拼接的 key 抓不到，所以**新代码尽量写完整字面量 key**。

### 114. 帮助弹窗：标题、文案与「一大堆字挤在一起」

- **需求**：25 个游戏的帮助标题统一「玩法介绍」；文案只讲玩法与计分，去掉关卡设置之类的冗余；排版要能扫读。
- **关键发现**：每个场景里都有一份自己的 `drawHelp()`，但 `App.render` 会把它**临时替换成空函数**再调
  `core/help.js` —— 也就是说场景里那份是死代码，改样式只改 `core/help.js` 才生效。
- **排版**：`core/help.js` 现在解析三种行首标记：`## 小标题`（主色 13.5 加粗、段前 10px）、`- 项目符号`
  （圆点 + 12px 悬挂缩进）、空行（段间距）；行高 20、折行宽 `W-104`。
- **文案**：25 个游戏的 `helpMsg` 全部重写为「怎么玩 / 计分（或胜负）」两段、3~5 条项目符号，
  旧的 `help1..helpN` 合并删除；中文控制在 ~260 字内（alchemy / legend / poker 规则多，约 310~370 字，面板可滚动）。
- **踩坑（写脚本改 i18n 时）**：
  1. 按 `helpMsg` 行整段删除要处理**跨行模板字符串**（反引号），否则会把后面的键一起吃掉；
  2. `re.sub` 的替换串里 `\n` 会被当成转义 → 插入的 `'...
...'` 会变成真正的换行、文件语法错误。
     要用 `lambda m: ...`（或纯字符串切片）来插入；
  3. 删键时若从 `cn: {` 这一行开始删，会把**块头**删掉 —— 范围要取 `start+1`。
  这次前两版都把 25 个 i18n 改坏了，靠 `git checkout HEAD -- js/games/*/i18n.js` 还原后重做
  （还原会丢掉未提交的 poker `guessRule`，要手动补回）。
- **验证**：冒烟逐个断言 `helpMsg` 以 `## ` 开头、≥2 条 `- `、长度在合理区间，并把 25 个帮助面板各画一遍
  （断言关闭按钮存在、不抛错）。
