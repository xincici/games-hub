# 小游戏迁移踩坑记录

> 用途：迁移下一个游戏之前先扫一遍；每个迁移任务结束时，把新踩到的坑追加到对应章节。
> 原则：**先记录症状，再记录根因和修法，最后写成以后不能违反的规则。**

## 一、Canvas / 图标 / 资产

### 1. 所有 icon font 图标看起来偏左

- **症状**：首页、home、help 等 UnoCSS / Iconify 图标整体偏左。
- **根因**：生成 TTF 时的横向平移只按 `(EM - glyphSize) / 2` 计算，没有按真实墨迹框 / em box 中心处理；不同端对 `textAlign='center'` 的实现也不完全一致。
- **修法**：`icons.draw()` 优先用 `measureText()` 的 `actualBoundingBoxLeft/Right` 把真实墨迹框居中；不支持时退回 advance 宽度。
- **规则**：所有单色图标只走 `icons.draw()`，不要在各场景手写 `fillText` 或重新算字体居中。

### 2. 首页 2048 图标显示成文字 / 图标缺失

- **症状**：某些新加 glyph 没有画出来，落到了文字 fallback。
- **根因**：字体缓存 / glyph 构建或 key 映射不一致。
- **修法**：确认 `build-icons.py` manifest、`icon-glyphs.js`、`HomeScene` 的 `glyphs` map 三处 key 完全一致；必要时用已稳定的 `calculator` glyph 兜底。
- **规则**：新增首页图标必须同时更新构建脚本、生成文件和首页映射；改完重新生成 TTF，不能只改场景。

### 3. 真机麻将牌变成 `Z2 / M3` 文字

- **症状**：模拟器正常，发布到真机后麻将牌是文字降级。
- **根因**：雪碧图使用 WebP，部分真机 canvas 对 WebP `drawImage` 支持不稳。
- **修法**：构建时转成 `images/mahjong-tiles.png`，启动时 `tiles.preload()`；加载失败才用文字降级。
- **规则**：牌面图片只用 PNG；`game.js` 启动预加载。

### 4. 麻将牌边框 / 圆角不对

- **症状**：牌面多一圈米色边框，或四角露出灰色方角。
- **根因**：雪碧图本身带底色和描边，外面又套了一层圆角底 / 1px 边框；同时 PNG 没有透明圆角，直接 `drawImage` 会带出方角。
- **修法**：先按统一 8px 圆角 `clip()`，再直接画雪碧图；**不要再套第二层边框**。
- **规则**：所有牌面统一走 `core/cards.js`；麻将正面 = 8px clip + 原图，背面 = 绿色斜纹 + 8px。

### 5. emoji 卡片大小 / 垂直位置不统一

- **症状**：连连看的 emoji 明显比对对碰 / 侦探大，而且位置偏上。
- **根因**：连连看自己按 `cell * 0.66` 画 emoji，并直接按 `middle` 基线；其他游戏走 `cards.draw`，比例是 `w * 0.42`。
- **修法**：所有 emoji 牌统一走 `core/cards.js` 的 `drawEmoji()`；尺寸统一 `w * 0.42`；优先用 `actualBoundingBoxAscent/Descent` 做墨迹垂直居中，再统一补 `0.30em` 视觉上浮偏移；不支持 actualBoundingBox 时退回 `middle` 基线。
- **规则**：emoji 卡片不允许各游戏自定字号和基线；空白格不画卡片，只有有牌的格子画。

### 5. 各游戏牌面各画一套，样式漂移

- **症状**：对对碰、侦探、猎手、消除大师的扑克 / 麻将 / 牌背不一致。
- **修法**：删除对对碰私有 `drawPoker/drawBack/drawMahjong`，全部走 `cards.draw()`；统一圆角 8、牌背、比例。
- **规则**：新游戏不允许写私有牌面；新牌面类型先扩展 `core/cards.js`。

## 二、布局 / 首页 / 弹层

### 6. 首页两行蜂窝垂直间距太大

- **症状**：上下行像两块独立网格，缝隙明显大于水平缝隙。
- **根因**：两行按 `2r + gap` 排，没有做蜂巢咬合。
- **修法**：行中心距离 = `2r - overlap`，`overlap = W * 40 / 750`（小程序 `-40rpx` 口径）；多行用 `step = 2r - overlap` 连续排。
- **规则**：首页蜂窝行间必须负 overlap 咬合，不能按普通 flex 间距堆叠。

### 7. 首页游戏名压图标 / 图标太小

- **修法**：7 格时 icon 区域 30、glyph 25；游戏名 12；新增到 25 格后用 4+3+4+3+4+3+4，保持行数奇偶交替。
- **规则**：增加游戏先算行数和卡片宽度，再调 icon / 字号，不要直接复制单行尺寸。

### 8. 设置抽屉 / 底部输入区离屏幕底部有缝

- **症状**：抽屉或 1A2B 键盘下面有一条背景色。
- **修法**：面板总高包含 `SAFE_BOTTOM`，底边贴屏幕底，安全区作为**内部 padding**；footer 文案放在安全区之上。
- **规则**：吸底面板不要用 `H - SAFE_BOTTOM` 当底边。

### 9. 结算遮罩重进后错位

- **症状**：退出重进侦探 / 猎手，胜负遮罩、牌面、按钮全部歪掉。
- **根因**：恢复 `level / board / phase` 后没有重新 `layout()`，仍沿用旧关卡的坐标。
- **修法**：restore 成功后立即 `layout()`；猎手遮罩只覆盖候选区，不盖上方目标区。
- **规则**：任何恢复局面的场景，restore 末尾必须重新布局；遮罩范围要按游戏区 rect 计算，不要用整个页面。

### 10. 胜负时底部 FAB 消失

- **修法**：渲染条件只排除 help / confirm，不再排除 WON / LOST / over。
- **规则**：结算层出现时，帮助和模式 FAB 继续显示。

## 三、转场 / 输入

### 11. 进入 / 退出游戏没有过渡

- **修法**：`App.openGame(id, origin)` / `goHome()` 用离屏 canvas 给旧场景拍快照；进游戏从卡片中心 `scale(0.08)→1`，回首页 `1→0.08`，320ms。
- **规则**：游戏内 home 一律 `app.goHome()`；不要直接 `openScene(home)`，否则没有收起动画。拿不到第二块 canvas 时退回即时切换，不能崩。

### 12. 弹窗按钮点不到 / 点穿

- **修法**：先加全屏 mask，再加面板按钮；`Input.find()` 从后往前扫描，后加的面板按钮优先。
- **规则**：所有 modal 的 mask 必须先 addButton，面板按钮后 addButton。

### 13. 过渡期间误触

- **修法**：`drawTransition()` 渲染时 `input.setButtons([])`，动画结束下一帧恢复正常。
- **规则**：场景切换 / 全屏转场期间不接收操作。

## 四、游戏逻辑 / 存档

### 14. 2048

- 分数是**盘面最大牌**，不是累计合并分。
- 存档的 `WIN` 恢复成 `GAMING`；`winShown` 保留，避免重复胜利。
- 新游戏直接开始，没有二次确认。
- 两阶段移动：先按 id 换格，130ms 后删掉被合并的两张、加一张新 id 的合并牌，再补新牌；不要用 ghost 隐形标记，容易永久消失。
- 合并弹跳 / 新牌缩放的 scale 必须在动画结束后回到 1，不能停在 1.16 / 1.1。

### 15. Threes

- 每张牌每次最多走一格，不是 2048 式滑到最远。
- 1+2=3，3 以上同数翻倍；1+1 / 2+2 不合并。
- 每张牌每步最多合并一次（`ahead.mergedThisStep`）。
- 得分 = 盘面所有牌分值之和，1/2 为 0。
- 1/2 牌堆平衡差 ≤ 4；`next` 预览也要一起存档。
- 新游戏打断旧的 140ms 落定回调，避免旧回调覆盖新盘。

### 16. 贪吃蛇

- 撞墙 / 撞自己都在 `unshift` 前判断；尾巴格也算身体。
- 默认穿墙，`__snake_game__through_wall` 只显式存 `'0'` 才关闭。
- 恢复进行中存档默认暂停，恢复失败存档保持失败且**不要播 lose**。
- 满盘时 `spawnFood` 要允许 `null`；`tick` 要判空。
- 暂停恢复要 3-2-1 冻结倒数，不能一按就继续。

### 17. 连连看

- board.js 用 `null` 表示空格，墙既挡连线路也挡放牌；棋盘外一圈是空的。
- `findPath` 最多 2 转折；路径可走到 `-1 / H / W` 外圈。
- 消除后如果无解，先 `shuffleBoard`，仍无解再 `generateBoard`；不能只洗牌。
- 新游戏二次确认；重玩本关不清最高关。
- emoji **保留卡片底**，但空白格 / 墙格不能画卡片底；墙用斜纹块；连线用 halo + 细线；外圈线在棋盘边缘外 0.14 格，首尾缩进 0.42 格。
- 消除时牌先闪烁（最多两次），闪烁结束再把两张牌和连线**同时**抹掉；不要在点击瞬间先清空 board。
- 棋盘起点 / 28px 提示带 / 连击 chip 位置对齐对对碰；连击小烟花和胜利礼炮都要有。
- 连击 2.5s 窗口，非消除点击要打断。

### 18. 消除大师

- 三种模式的 `mode / level / state` 全部独立；切模式前保存当前状态，切回恢复。
- 状态必须实时保存（拿牌、三消、失败、胜利、切后台），不能只保存胜利。
- 恢复时恢复 tiles/tray/level/phase；`tileId` 接续最大 id，避免新 id 冲突。
- 暂存槽形状跟牌面走：emoji 1:1、扑克 2:3、麻将 131:168；槽底、飞行卡、消除卡共用同一个 rect。
- 初始化逐张入场、飞入槽位、三消闪烁都要有；飞行目标用 slotRect，不能写死正方形。

### 19. 侦探 / 猎手

- 观察倒计时用沙漏，作答已用时间用秒表。
- 进入 ANSWER 前：目标牌翻回背面，候选区同时翻正；找回目标后对应目标牌再翻正。
- 猎手的胜负遮罩只盖候选区，保留上方目标区。
- 恢复结算后必须重新布局（见第 9 条）。

### 20. 全部模式的共同存档规则

- key 与 web / 小程序一致，不要改名。
- 恢复只接受结构合法的状态；字段 id / emoji / 坐标 / 关卡要校验。
- 结算局面可以恢复，但恢复时不要重播烟花 / 音效。
- 分享 / 切换模式 / 退出前先落档。

## 五、计时器 / 控件

### 21. 计时器图标不统一

- **规则**：正计时一律秒表 `stopwatch`，倒计时一律沙漏 `hourglass`，统一走 `core/timer.js` 的 `drawTimer()`。
- 目前：2048 / Threes / 1A2B 已用时间 → 秒表；Match / Link 限时、侦探 / 猎手观察 → 沙漏；侦探 / 猎手作答时间 → 秒表。
- 不要再用 `⏳` / `⏱` 文本当计时图标。

### 22. 难度步进器样式不统一

- **规则**：参考关灯游戏：28×28 描边小按钮、8px 圆角、数字 18px 加粗、点击热区外扩 8px、三格布局 30% / 65% 分隔。
- Snake 已对齐；后续有 `− n +` 的区域直接复用这套参数。

## 六、动画 / 撒花

### 23. 配对闪烁次数太多

- **规则**：所有配对 / 消除闪烁统一用 `core/motion.js` 的 `matchedMotion(age)`：最多两次明暗循环；不要按固定 80ms 硬切。

### 24. 撒花过度集中 / 落在两侧

- **规则**：左右礼炮，目标带 `center ± W*0.28`，越过中线后收住水平速度，只保留重力；不要回到单点喷发或只落两侧。

### 25. 动画 scale 不归位

- 合并 / 新牌 / 闪烁的 scale 必须按时间 clamp 到 1；动画结束后不能停在放大值。

### 26. 首页所有游戏都用同一个绿色

- **症状**：首页边框和图标全是主色，分类感丢失。
- **修法**：按 web / 小程序的 accent 分类上色：logic #23804e、number #2c6aad、memory #7550ad、action #bd5420、card #8f6419；六边形外层用 18% 混色（#abc2c1 / #adbed2 / #bab9d2 / #c7bab9 / #bfbdb7），图标用完整 accent。
- **规则**：新增首页游戏必须同时给 `accent`，不能默认主色；首页布局按 4/3/4/3… 动态分行。

### 27. Emoji 镜像恢复局面时展示区和游戏区数量不一致

- **症状**：恢复存档后 rows / 卡牌错位，或游戏区出现空位。
- **根因**：只校验了 `display.length` 和“当前难度”其中一个，条件写反时另一种情况会漏过。
- **修法**：先按 `saved.difficulty` 算出 expected，再要求 `display.length === expected && game.length === expected`；恢复后重新 layout。
- **规则**：镜像展示区和游戏区必须同长度、同样行数；开局 `derange` 保证零匹配，游戏区在展示阶段保持背面。

### 28. Emoji 下坠牌堆被消除后出现空档 / 越界

- **症状**：消掉顶排后底部空出一条，或堆被推出棋盘。
- **根因**：只 `shift()` 没有补底，或 `top` 没有钳在合法范围。
- **修法**：`clearRow` 后 `top = min(ROWS-1, top+1)`，立即 `fillPile()`；每一帧上升后也 `fillPile()`；`top - 1 <= 0` 判负。
- **规则**：牌堆必须始终从顶排连续铺到棋盘底，不能有空档；点列只移动玩家列，不改变牌堆结构。

### 29. 数字迷宫洗出不存在的局面

- **症状**：滑块局无解。
- **修法**：从完成态开始随机走合法相邻步，保证可解；不要直接 `shuffle` 数字。
- **规则**：滑块类游戏只从完成态打乱。

### 30. Emoji 镜像没有动画

- **症状**：展示区一出现就是最终状态，交换也没有移动，整个游戏像静态表格。
- **修法**：按阶段推进：`REVEAL`（展示 1.2s）→ 逐张 `FLIP_DOWN` → `GATHER` 聚到展示区中心 → `FLY_BACK` 飞回 → 逐张 `GAME_FLIP` 翻正 → `PLAY`。交换用 300ms 两张牌对向位移，位移结束后再交换数据并进入 450ms `CHECK`。
- **规则**：镜像的展示、洗牌、翻面、交换都必须有过渡；不要直接把 phase 置为 PLAY。
- **补充坑**：`startRound()` 里曾把 `displayFlips / gameFlips / displayOffsets` 重置成空数组，渲染时取不到值就 fallback 成正面 / 无位移，看起来完全没有动画。每开一局必须按新 `round.display.length` 重新填满这些数组。

### 31. 动画字段加了但忘了在 update 清理

- **症状**：数字迷宫点一次后所有数字都不再响应，移动中的牌一直停着。
- **根因**：`onCell` 设置了 `moveAnim`，但 `scene` 根本没有 `update(dt)`，没人把动画状态清掉。
- **修法**：所有动画字段都必须有对应的 `update` 推进 / 到期清理；新增动画后检查 `this.xxxAnim` 是否会在 140~350ms 后归零。
- **规则**：不能只在 render 里读动画时间，必须有 update 生命周期。

### 32. 打开帮助后游戏还在跑

- **症状**：看帮助时贪吃蛇仍在移动、计时器仍在涨、侦探观察阶段继续跳转。
- **修法**：`update()` 在 `helpOpen || confirming` 时直接返回（或冻结计时/定时器）；关闭后再继续。
- **规则**：所有 modal 打开期间冻结游戏逻辑，不能只画遮罩。

### 33. 恢复镜像存档时展示区被翻开

- **症状**：退出重进后本应藏起来的展示区直接显示答案。
- **根因**：restore 把所有 flips 初始化成 1。
- **修法**：PLAY 恢复时展示区 flips 为 0、游戏区为 1；只有 WON 才让展示区翻开。
- **规则**：恢复状态必须按 phase 决定牌面朝向，不能一律正面。

### 34. 对对碰配对闪烁时整盘锁死

- **症状**：消掉一对后，闪烁还没结束，点其它牌完全没反应。
- **根因**：配对成功时把全局 `lock` 设为 true，等 470ms 后才在 `resolveMatch` 释放；这段时间所有牌都被拦住。
- **修法**：配对成功立即把两张标记为 `matched` 并启动闪烁，不设置全局 lock；只让不匹配的翻回动画使用 lock。这样其它未翻牌可以在闪烁期间继续操作。
- **规则**：动画期间的输入锁只锁“同一对牌”，不要锁整盘；匹配牌本身通过 `matched` 排除点击。
- **同类**：Emoji 连连看也曾用 `pendingClear` 在 520ms 闪烁期间拦住 `onCell`，导致其它牌不能点。修法是：逻辑上立刻把两张牌置空，渲染层保留一组 `clears` ghost + 连线做闪烁，结束再移除 ghost；其它牌继续可点，路径自然绕开已置空的位置。后续任何消除动画都按这个模式做。

### 35. 24 点算式偏右、禁用符号不明显

- **症状**：算式整体偏右；不能点的 + − × ÷ 和可点状态几乎一样。
- **根因**：算式左侧预留了 34px，右侧又给退格留空间，导致可用区域中心偏右；操作符底板不管 enabled 都用浅色 enter。
- **修法**：算式按卡片中心 `W/2` 居中，最大宽度对称扣掉退格区域；操作符可点用白底 + 主色描边 + 主色字，不可点用 `T.disabled` 灰底 + 灰字。
- **规则**：带右侧工具按钮的居中文本，按整体中心排版，不要一边多留空白；禁用态必须换底色，不能只换文字颜色。

### 36. Threes 只做松手滑动，没有跟手和 95% 提前提交

- **症状**：滑动时牌不动，必须松手才动；拖到 90% 松手也没有合并，像普通 swipe。
- **参考行为**：Slop 10px 锁定方向；只让本步会移动的牌跟随手指；拖动超过 50% 松手提交，超过 95% 直接提交；不足 50% 弹回。
- **修法**：`onTouchStart/Move/End` 维护方向锁、movers、dist；渲染时只给 movers 加 `dir * dist` 偏移；提交后再走原有 130ms 落定 / 合并。
- **规则**：Threes 不能只做 swipe-only；以后类似“跟手滑动 + 松手提交”的游戏统一用这个 10px / 50% / 95% 参数。

### 37. 游戏卡片分隔线太长

- **症状**：分数卡 / 操作卡里的竖分隔线几乎顶到卡片上下边，和缩小的分栏内容不协调。
- **参考**：小程序 `.divider` 高度为 48rpx（约 24px），垂直居中；不是 `卡片高 - 28`。
- **修法**：统一用 `core/draw.js` 的 `D.divider(c, x, centerY, 24, color, 1)`；分数卡按 `scoreY + scoreH/2`，操作卡按 `optY + optH/2`。
- **规则**：以后所有游戏卡片内分隔线固定 24px 高、垂直居中；不要再按卡片上下内边距自动撑满。

### 38. 分数卡进度条戳出卡片圆角

- **症状**：带进度条的分数卡，底部横条两端是直角，和 14px 圆角卡片不协调。
- **根因**：进度条直接 `fillRect` 卡片全宽，没有裁切到卡片的圆角路径。
- **修法**：用 `core/draw.js` 的 `D.progressBar(...)`：先按卡片 14px 圆角 `clip()`，再画轨道和进度；禁止直接画满宽横条。
- **规则**：以后所有贴在卡片边缘的进度 / 高亮条都必须先裁到卡片圆角。

### 39. 镜像操作区不等分 / 洗牌没有重叠散开

- **症状**：难度区只占卡片左侧约 30%，新游戏按钮很宽；洗牌时牌像平移回原位，没有“叠起来再散开”的感觉。
- **修法**：难度步进器和「新游戏」各占操作卡 50%；洗牌阶段拆成 `GATHER`（叠到中心）→ `STACK`（重叠停留 240ms）→ `FLY_BACK`（随机延迟散射回各自位置）→ `GAME_FLIP`。
- **规则**：镜像操作区和其它双栏操作卡保持等分；洗牌不能只做同速直线归位，必须有重叠停顿和错峰散开。

### 40. 初始化 / 恢复动画没有按左上到右下依次出现

- **症状**：数字迷宫开局所有数字同时弹出；其它游戏候补牌有些是斜线波浪、有些按数组随机顺序。
- **规范**：所有开局 / 恢复时需要入场的卡片、数字、牌面，统一按**行优先 index** 错峰：`index = row * cols + col`，每格约 20~45ms，先左上后右下。
- **不要**用 `row + col` 做斜线波浪，也不要按 shuffle 后的数组顺序。
- **修法**：先算 row-major rank，再给每张牌/数字赋 `dealAt / delay`；恢复时如果需要播入场动画，同样按这个顺序。
- **操作区**：双栏操作卡（难度 + 新游戏）默认 **50 / 50 等分**，不要一边 30% 一边 70%。数字迷宫已改为等分。

### 41. 难度 `− 数字 +` 被拉到两端

- **症状**：数字迷宫 / Emoji 镜像的操作区里，减号贴最左、加号贴分隔线，数字悬在中间，三个元素之间空隙很大。
- **修法**：把 `− 数字 +` 作为一个整体组，按 `28 + 12 + 数字宽 + 12 + 28` 计算组宽，在左半区居中；不要分别用左右边距定位。
- **规则**：所有难度步进器都按“组内紧挨、整组居中”布局，不能两端对齐。

### 42. 恢复存档播放入场动画时用了不存在的尺寸字段

- **症状**：Threes 恢复后 `dealing` 永远不清，或动画延迟为 NaN。
- **根因**：`restore()` 里写了 `this.n * this.n`，但 Threes 没有 `this.n`，实际常量是 `SIZE`。
- **修法**：恢复入场动画用实际存在的 `SIZE / rows / cols`；如果场景没有某个字段，不要照着其它游戏复制。
- **规则**：restore 分支也要跑类型 / 字段自检，动画时间不能出现 NaN。

### 43. 消除大师没有按层入场

- **症状**：开局 / 恢复时牌面同时出现，或先按行坐标出现，底层牌压在上面才出现。
- **参考**：从最下层开始逐层往上，每层内再按 `x/y` 左上到右下。
- **修法**：`prepareDeal()` 按 `layer → y → x` 排序生成 `dealOrder`；每张延迟 `rank * 25ms`，`restore()` 也要调用。
- **规则**：分层堆叠类游戏的入场顺序以 layer 为第一关键字，不能只按平面坐标。

### 44. 选对 / 选错只换边框颜色

- **症状**：侦探 / 猎手选错只是变红，选对只是变绿，缺少动作反馈。
- **修法**：抽 `core/fx.js`：选错 `wrongShake(age)`（350ms、±4px、幅度衰减）；选对 `popScale(age)`（450ms 一次性：1 → 1.18 → 0.96 → 1.04 → 1）。
- **接入**：侦探的错误牌晃动、正确牌弹一下；猎手的错误候选晃动、找回的候选弹一下；边框颜色保留作为静态状态。
- **规则**：正确 / 错误反馈不能只靠颜色；选对是一次性 pop，不是持续呼吸循环。

### 45. 选错音效和失败音效混用

- **症状**：侦探 / 猎手点错时直接播 `lose`，和整局失败听起来一样，扣心没有独立反馈。
- **参考**：小程序选错播 `fail.mp3`，整局失败才播 `lose.mp3`。
- **修法**：`core/audio.js` 增加 `playFail()` 和 `audio/fail.mp3`；选错（扣❤️）用 `playFail`，`hearts <= 0` / 结算失败再用 `playLose`。
- **规则**：`fail` = 单次操作错误，`lose` = 整局失败，不能互换。

### 46. 胜利烟花又紧又规律

- **症状**：碎片都从两侧固定高度、固定速度飞向屏幕中线附近，大小/形状几乎一样，看起来像两束整齐的粒子。
- **修法**：统一用 `core/confetti.js`：
  - 落点 `targetX` 在 10%~90% 屏宽随机，不再全挤在中线；
  - 起点 y 在较大范围抖动；
  - 初速度、重力、旋转速度随机；
  - 形状随机 rect / circle / ribbon / triangle；
  - 尺寸 3~10px 随机。
- **规则**：所有游戏胜利烟花统一走 `confetti.spawn/update/draw`，不要在各场景复制固定 5 颗、固定目标的版本。

### 47. 真机图标偏左、emoji 偏下

- **图标偏左**：真机 canvas 对自定义 icon font 的 `actualBoundingBoxLeft/Right` + `textAlign` 组合不可靠，按墨迹框算出来的中心仍会左偏。
  - 修法：`icons.draw` 用离屏 canvas 画一次 glyph，扫描 alpha 得到真实墨迹左右边界，缓存每个 glyph+size 的居中偏移；探针不可用时再退回中心对齐。
- **emoji 偏下**：`drawEmoji` 之前统一加 `0.30em` 的光学下移，真机上会过度下沉。
  - 修法：收到 `0.18em`，仍保留 actualBoundingBox 的垂直墨迹居中。
- **规则**：真机居中不要只信 measureText；icon font 用像素墨迹探针，emoji 用较小的光学偏移。

### 48. Threes 松手后先回原位再播放移动

- **症状**：拖动跟手到 50%~95% 松手，牌先跳回原来的格子，再重新播放一次移动动画。
- **根因**：`move()` 的 `fromRow/fromCol` 用的是拖动前的整数行列；松手时把 `drag` 清空，渲染先回到出发点，再开始补间。
- **修法**：`move(dir, startDist)` 接收松手距离，把移动牌的起点设为 `before + dir * (startDist / pitch)` 的**小数坐标**，动画从当前手指位置直接接到目标格。
- **规则**：所有跟手拖拽 + 松手提交的动画，补间起点必须是当前拖动位置，不能回到原格再播。

### 49. 首页加到第 6 行后顶部顶到副标题

- **症状**：25 格（4+3+4+3+4+3+4）七行下，375×667 上第一行六边形会顶到 `homeSubtitle`。
- **修法**：蜂窝中心下移到 `H * 0.51`（限制在 `H - 190`）；7 行布局需要按「标题下沿到齿轮上沿」的竖向预算反算半径；375×667 顶部约 98px、390×844 约 141px。
- **规则**：首页增行后必须同时检查 375×667 和 390×844 的顶部/底部/FAB 三处边界。

### 50. 数独数字键盘和右下 FAB 重叠

- **症状**：数独键盘铺在底部后，帮助 / 候选 FAB 直接压在数字键或工具键上。
- **修法**：不要只挪 FAB 的 y 让它覆盖键盘；在键盘上方单独留一条 40px 的 action row（右对齐，左边放难度名），棋盘底 = action row 上方 8px，键盘再下方。375×667 上棋盘缩到约 277px，390×844 上约 358px。
- **规则**：底部有整块键盘 / 按钮行时，FAB 必须独占一行或放到标题栏，不能覆盖可点区域。

### 51. 交互细节回归（本轮）

- **镜像**：交换后必须显示“计算中…”转圈，`CHECK_MS = 500`，结束后才显示对齐数；不能交换完立刻显示结果。
- **数字迷宫**：除点击外必须有滑动方向操作；滑动目标按空白格反方向取邻格。
- **下坠**：点击换列先走 150ms 横移动画，落位后再判消除；消行后旧行 180ms 下落，落定后若新顶排与手中 emoji 相同直接连锁；顶排 220ms 膨胀淡出。
- **连连看**：无可消对先显示 0.65s 提示，再洗牌；洗牌时牌面缩小/旋转/错峰恢复，不能瞬间换盘。
- **1A2B**：机器人 / 帮助 FAB 与退格/提交行垂直居中，键盘底部只留 10px，不能贴屏幕底。
- **猎手**：目标区找到后的绿色提示只描边，不要用半透明色块盖在牌面上（会把翻正的 emoji 压到背景层）。
- **消消乐 / 排序 / 滑行图标**：必须用小程序首页同款 `star-four-points` / `test-tube` / `arrow-all`，不要用近似图标。

### 52. 数独圆角 / 候选模式 / 难度文案

- **圆角被盖**：棋盘外层圆角填完后，内层仍用 `fillRect`，会盖掉外框四角的圆角。外框和内层都必须 `fillRoundRect`，内层半径 = `boardR - frame`。
- **候选模式**：不要保留“先切换候选模式、再逐格填候选”的交互；`候选` 按钮就是一次性填满所有空格的全部候选。笔记仍可保留为独立手动标记。
- **帮助位置**：帮助 FAB 保持在右下角老位置；键盘工具行右侧预留 48px，不要为了避让把 FAB 挪到键盘上方。
- **难度文案**：`− 简单/中等/困难 +` 的文案放在两按钮中间，不要单独占一行或只显示数字。

### 53. Emoji 排序点不动 / 背面图标不对

- **排序点不动**：`metrics` 漏了 `cell` 和 `headH`，槽位点击热区高度变成 `NaN`，Input 永远命中不了。补 `cell/headH`，热区高度直接用 `boardH - PAD`。
- **背面图标**：只要有扣着的 emoji 牌，牌背必须使用该游戏在首页的 icon，不能统一用灯泡：
  - 对对碰 `bulb`；侦探 `incognito`；猎手 `target`；消除大师 `layers`；镜像 `mirror`；排序 `sort`（试管的 Iconify glyph）。
  - 通过 `cards.draw(..., faceUp, backIcon, backFallback)` 传入；`cards.drawBack` 默认仍是 bulb，只给没传的老场景兜底。
- **检查范围**：所有 `cards.draw(..., false)` / `faceUp` 可能为 false 的 emoji 场景；扑克 / 麻将牌背仍走各自牌背，不受这条影响。

### 54. 数独操作区 / 帮助 / 工具图标

- **难度组溢出**：`− 6px 难度名 6px +`，按钮 24px；不要再沿用 28px + 10px 的宽组，左三分之一放不下。
- **固定间距**：棋盘顶边距操作卡 12px；操作区顶边距棋盘底边 12px；只缩棋盘，不把棋盘/键盘在剩余空间里居中。
- **操作区全宽**：操作卡宽度必须与上方卡片一致；不要为了给帮助按钮让位而缩窄。
- **帮助不侵入**：键盘下方预留 56px（40px 帮助按钮 + 8px 间隙），帮助 FAB 放在操作卡下方、不压键盘/工具行。
- **工具图标**：参考小程序 `format-list-numbered` / `pencil-outline` / `backspace-outline`；图标和文字作为整体居中，间距 5px，不能图标靠左、文字单独居中。候选主色、笔记蓝紫、擦除红色。

### 55. 镜像洗牌不流畅

- **症状**：聚拢末尾有轻微跳动，飞出瞬间卡片从 0.82 缩放突然跳到 1，个别牌像卡一下。
- **修法**：不要逐帧指数插值；用阶段时间做 easeOut：
  - `GATHER`：从当前位置到中心，420ms；
  - `STACK`：位移精确锁定中心，缩放 0.82；
  - `FLY_BACK`：每张按 90ms 错峰，位移和缩放（0.82→1）一起缓动；
  - 飞出结束一帧把位移归零、缩放归 1，再进入 GAME_FLIP。
- **规则**：洗牌类动画必须时间驱动、缩放与位移同步，动画结束显式归位。

### 56. 25 格首页与后续新游戏

- 首页 25 格用 `4+3+4+3+4+3+4` 七行；半径同时受宽度和竖向预算约束，375×667 顶部约 98px、390×844 约 141px。
- 扑克牌背用 `mode-poker`，图标尺寸 `max(16, w*0.60)`（旧 0.34 太小）；麻将英雄 / 单人麻将 tile 背面走麻将纹理，不要套 emoji 规则。
- 新游戏注册后必须同步 `js/games/index.js`、`game.js`、`GAME.js` 三处；首页卡片、icon、accent、i18n 四处。
- 扑克 5 张牌、麻将 3×3、单人麻将 14 张手牌/牌墙都必须用 `cards.draw`，不要另写牌面。

### 57. 结算遮罩 / 心形标签 / 返回键图标

- **遮罩太快**：新打出的 WON/LOSE 遮罩统一走 `Scene.resultVisible(250)`；先让最后一帧动画（翻牌 / 消除 / 落子）播完，再等 250ms。不要直接 `phase=WON` 后立刻铺遮罩。
- **恢复例外**：退出重进时如果场景第一帧就是结算态，`_hasRendered=false`，`resultVisible()` 立即放行，不能补 250ms。
- **心形旁小方格**：生命标签不要再写 `❤️ Lives` / `❤️ 生命`，生命图标单独画；文案里也不要混 `❤️`，避免真机 VS16 变方块。已清理侦探 / 猎手 / 数独。
- **1A2B 退格**：图标和“退格”文字必须作为一组居中，间距 5px；不能图标靠左、文字单独居中。
- **下坠消行**：只让玩家牌下落，下方已经存在的行位置保持不动；不要给整排加 fallOffset。
- **蛇暂停/继续**：与下坠统一主色实心 + 白字，不要一个描边橙、一个实心绿。

### 58. 德州扑克区域顺序 / 猜大小 FAB / 牌型遮罩

- **区域顺序**：严格按小程序：牌型倍数区 → 金额区 → 5 张手牌 → 猜大小区 → 操作区；不要按 web 的金额在前。

- **猜大小区**：高度 200rpx（约 100~104px），历史/当前牌使用同一 mini 尺寸 76:114，历史可横向拖动；卡片顶部不要再放「猜对奖金加倍」文案。
- **中牌遮罩**：只覆盖牌型区，透明度约 0.95；牌型名 + 倍数 + 仅遮罩内的小烟花，**不要**启动全屏胜利礼炮。

### 60. 首页标题 / 扑克 / 镜像结算 / 迷宫胜利 / 单人麻将

- **首页**：去掉「游戏合集」「选择一个游戏」两行，不要用空字符串占位；蜂窝仍按标题下方的预算布局。
- **扑克**：牌型区 `16px caption + 23px 行高`；发牌区自然高度 `cardH + holdH + 12`、额外高度最多 40；猜大小非开牌阶段右侧常驻牌背（不是问号占位）；中牌型只播 `playElimination` + 奖金区上方小烟花，不播 `playSuccess`、不铺全屏礼炮；点击结算落袋时才 `playSuccess` + 全屏礼炮。资产 / 奖金任何变化都由 update 对比上一帧，给数字触发 popScale。

- **单人麻将**：牌堆高度 88、紧贴上边；弃牌飞行 320ms 结束后才摸牌（DRAW_DELAY 340）；牌堆旁不要「牌墙」文字和数字。

### 61. 炼金候选卡 / 雀圣棋盘背景 / 赌神答案区

- **扑克炼金术**：候选牌 + 新游戏按钮放进 `drawRow` 的卡片，位置在棋盘上方（`rowY` 先于 `boardY`），与麻将英雄一致；左右各占半区居中，中间不要「点空格放入」提示，新游戏按钮使用 🎮 前缀（与其它游戏一致）。候选牌 36×54 并在 66 高卡片内垂直居中，牌背内缩 1px；高亮边框必须在同一个 `translate/scale` 里画，并和牌面共用 `x/y/w/h` 与 `cards.pokerRadius(w)`；预览牌按 0.8/0.6 缩放时圆角也随宽度缩小。
- **雀圣**：`drawBoard` 先画整块 `T.boardBg` 圆角背景 + 边框，再画每格；只画格子会看起来「游戏区没有背景」。
- **赌神**：答案区空的时候不要画虚线槽位框；参照小程序只留卡片和文字提示。

### 62. 雀圣按钮 / 背景

- **候选操作卡**：新游戏 + 上帝模式各占一半；帮助不要再塞在操作卡里。
- **撤销 / 重做**：放在棋盘下方的独立卡（宽约 82.93% 屏宽），不要塞回标题栏。
- **右下角**：模式切换 + 帮助两个 FAB；模式切换沿用 `__quesheng__mode`，两套 state/level key 分开。
- **棋盘背景**：先画整块 `T.boardBg` 圆角底板再画格子，否则会像「游戏区没有背景」。
- 上帝模式播放期间 `canUndo/canRedo` 必须禁用，触摸 / 帮助 / 新游戏要先 `stopGod()`。

### 63. 雀圣图标 / 关灯撤销 / 候选牌

- 雀圣「新游戏」用 🎮 前缀、「上帝模式」用 ⚡ 前缀（与关灯游戏一致）；不要把 🎮 / ⚡ 换成 add / robot 图标。
- 雀圣消除浮影严格照小程序 `qs-blink 0.52s`：透明度 1→.15→1→.15→0，缩放 1→.72，结束移除；不要复用 `motion.matchedMotion` 的 1.4s 缩小 / 下落。播放中按钮文案是「⏸ 暂停」。
- 麻将英雄候选牌之间不画 `→`；预览牌圆角用 `cards.mahjongRadius(w)` 随宽度缩小。扑克炼金术候选牌必须在卡片内居中，不能和卡片同高。
- 关灯游戏的撤销 / 重做改为雀圣同款：整张卡片平分左右、无描边药丸、图标 + 文字居中，禁用时整组 0.4 透明。
### 64. 首页拖动排序

- 小游戏首页进入时按小程序 `hex-pop` 逐格跳动：0.82→1.09→0.97→1，延迟/时长按 id 哈希；用模块级 `homeIntroPlayed` 保证只在首次进入播一次，返回首页不重播。
- 小程序源码在 `mp/src/`，但微信开发者工具导入的是构建产物 `mp/dist/build/mp-weixin/`：改完源码必须 `cd mp && npm run build:mp`，否则页面看起来完全没变。
- 小程序 / 小游戏 / web 共用顺序 key `__games_hub__home_order`（JSON 数组，元素是游戏 id）。
- 长按 **260ms** 才进入拖动；移动超过 12px 先取消长按；拖动时原卡降透明度、手指位置画半透明替身。
- 经过另一张卡时直接交换 order 中两项并落盘；新游戏按默认注册顺序追加到末尾。
- 小游戏画布版没有 DOM `elementFromPoint`，用每个 hex 的按钮矩形做 hit test；交换后 `layout()` 重建格子，`drag.id` 保持不变。
- 拖动结束要吞掉随后那次 click / tap，否则松手会误进游戏。
- 设置弹窗底部的「长按卡片可拖动排序」和 `have fun` 放同一行；小程序提示条要有浅底/正常文字色，不要用太浅的 footer 小字。
